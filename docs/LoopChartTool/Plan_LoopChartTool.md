# Plan — Loop 모드 채보 굽기 (Pattern Chart Tool 이원화)

근거: `Research_LoopChartTool.md`. 런타임 쪽은 `docs/StageClearCondition/Plan_StageClearCondition.md`이며 **그 계획이 먼저 확정돼 있어야 한다**(여기의 검증 항목이 거기서 정해진 규칙을 그대로 강제한다).

---

## 0. 설계 결정 — 다섯 줄

1. **중간 표현과 저장 경로는 하나다.** `ChartEntryDraft`와 `Save()`를 공유하고, 두 모드는 **그것을 채우는 방법**만 다르다. `SongChart` 스키마는 엔트리 쪽이 한 필드도 안 바뀐다.
2. **Linear는 한 줄도 안 고친다.** 분석 파이프라인(`OnsetDetector`·`OnsetGrouper`·`OnsetChunkSplitter`·라운드로빈 배정)은 **Linear 전용으로 격리**될 뿐 삭제하지 않는다.
3. **Loop는 분석기가 아니라 스텝 시퀀서다.** 마디 격자 위에 엔트리를 놓고, 드래프트가 **스텝 인덱스를 든다**(초가 아니라).
4. **지금까지 음악이 공짜로 주던 제약을 툴이 강제한다** — 엔트리 간 최소 간격·노출·마지막 엔트리 역할·루프 길이(R-T10~T14). **이게 새 코드의 절반이다.**
5. **한 창에 모드 토글**(연구 §4의 A안). 창을 둘로 나누면 저장 검증이 복제되고 그중 하나만 고치는 날이 온다.

### 0-1. Loop 드래프트가 추가로 드는 것

```csharp
private class ChartEntryDraft {
    // ── 기존 (두 모드 공유) ─────────────────────────────
    public Pattern template;
    public float[] onsetTimes;          // 절대 시각(초) — 저장 형식
    public float[] exposureDurations;
    public float[] spawnTimes;
    public EnemySpace.EnemyCue enemyCue;

    // ── Loop 전용 ───────────────────────────────────────
    public int[] onsetSteps;            // ⚠ 진실의 원천. onsetTimes는 여기서 파생된다
}
```

**⚠ `onsetSteps`가 없으면 BPM을 고치는 순간 배치가 격자 밖으로 밀린다**(연구 §3-3). Linear 드래프트에서는 `null`이고, **그 null 여부가 곧 "이 드래프트가 어느 모드 것인가"**다 — 별도 플래그를 두지 않는다.

## 단계

### - [ ] Step 1 — 새 필드 둘 (`SongChart`)

```csharp
[Min(1)] public int beatsPerBar = 4;
```
- **⚠ 런타임도 쓴다.** 드리프트를 마디로 올림하는 선택지(StageClearCondition Plan Step 4)와 루프 규격 검사가 이 값을 요구한다. `bpm`·`beatOffset` 옆이 제자리다(곡의 성질).
- **⚠ `BeatGrid`는 이 값을 모른다**(`subdivisionsPerBeat`만 안다, BeatGrid.cs:12). 마디 계산은 툴/런타임이 하고 `BeatGrid`는 그대로 둔다 — 그 struct는 Unity 비의존 순수 코어라 개념을 늘리지 않는다.

```csharp
public enum ChartAuthoring { Linear, Loop }
public ChartAuthoring authoredWith = ChartAuthoring.Linear;
```
- **⚠ `StageMode`와 다른 물건이다.** 이건 *"어느 편집기로 열까"*이고 런타임은 안 읽는다 — `patternPool`과 같은 성격이며 주석에 그 선례를 적는다(SongChart.cs:46).
- **⚠ 기본값이 `Linear`여야** 기존 채보 17개가 지금 편집기로 열린다(회귀 0).
- `Loop`인 채보를 Linear 편집기로 열면 **`분석` 버튼을 비활성**한다(저작이 통째로 날아가는 유일한 경로).

### - [ ] Step 2 — 모드 토글과 구역 분기 (`PatternChartWindow`)

`OnGUI`(:100~129) 상단에 모드 툴바. 구역별 분기:

| 구역 | Linear | Loop |
|---|---|---|
| 음원 / 대상 SongChart | 그대로 | 그대로 |
| 패턴 풀 | 자동 배정 재료 | **팔레트**(문구만 다르다, 연구 §3-4) |
| 분석 파라미터 | 그대로 | **숨긴다**(`rmsThreshold`·`windowSize`·`maxGroupGapSteps`) |
| BPM 격자 | 그대로 | `beatsPerBar`·`stepsPerBeat` 추가, `tier1Max`/`tier2Max` 숨김 |
| 액션 버튼 | `분석` / `불러오기` | **`격자 세우기`** / `불러오기` |
| 파형 | `DrawWaveform` | **마디 격자 캔버스**(Step 3) |
| 엔트리 목록 | 그대로 | 그대로 + 스텝 표시 |
| 저장 | 그대로 | 그대로 + 검증(Step 5) |

- **⚠ `level → subdivision` 매핑을 Loop에서 쓰지 않는다.** `BeatGrid.LevelToSubdivision`은 "레벨이 높으면 잘게 썬다"인데 격자 저작에서는 저작자가 해상도를 직접 고른다. `level`은 `SongChart`의 표시용 난이도로 남는다.
- **⚠ 모드 전환 시 드래프트를 버리지 않는다** — 경고만 띄우고 유지한다. Linear로 구운 채보를 Loop 편집기에서 다듬는 것은 **유효한 작업 흐름**이다(온셋이 이미 격자에 스냅돼 있으므로 스텝으로 환산된다).

### - [ ] Step 3 — 마디 격자 캔버스

`DrawWaveform`(:~429) 자리를 대체한다. 좌표는 `BeatGrid`가 그대로 준다 — **새 수학이 0이다.**

- 가로 = 스텝, 세로 = 마디(마디당 한 줄). **⚠ 한 줄로 길게 늘이지 않는다** — 4마디만 돼도 스텝이 64개라 가로 스크롤만 남는다.
- 마디 머리에 굵은 선, 박 머리에 중간 선, 스텝에 얇은 선.
- 엔트리는 **첫 온셋부터 마지막 온셋까지 잇는 막대**로 그리고 노드마다 점. 선택 시 강조(기존 `selectedEntry` 관용구 재사용).
- **⚠ 캔버스 길이가 `clip.length`에서 안 끝난다**(R-T15). `barCount`를 곡 길이에서 유도하되 **저작자가 늘릴 수 있게** 한다 — 루프 2~3바퀴를 쓰는 채보가 정상이다. 곡 1바퀴가 끝나는 마디에 **경계선**을 긋는다.
- 클릭으로 배치, 드래그로 이동, 선택 후 `Delete`. **⚠ 리스트 변경은 그리는 도중에 하지 않는다** — 기존 `pending` 액션 큐(:83)를 그대로 쓴다(안 그러면 `GUILayout`이 터진다).

### - [ ] Step 4 — 배치 모델

엔트리 = **(시작 스텝, 노드 간격 스텝, 템플릿)**. 온셋은 `start + i × gap`으로 자동 생성되므로 **격자 위에 있는 것이 구조적으로 보장**된다.

- **⚠ "노드 수 = 온셋 수"가 표현 불가능한 불일치가 된다.** 현행 툴이 `RecomputeSpawnTimes`에서 검사해 `spawnTimes = null`로 막던 그것(:382~391)이 **이 모델에서는 생길 수 없다.** 검사는 남겨 둔다(Linear가 계속 쓴다).
- 불규칙 리듬은 **행 편집에서 온셋을 스텝 단위로 개별 이동**. 그 경우에도 값은 스텝이라 격자를 벗어날 수 없다.
- 연타는 **(시작 스텝, 끝 스텝)** 둘. `ConvertToMash`(:1135)는 **Loop에서 훨씬 단순해진다** — 양 끝만 남기는 게 아니라 처음부터 둘이다.
- `onsetTimes` = `BeatGrid.GridIndexToTime(step)`으로 **매 편집마다 재계산**한다. BPM/offset을 고치면 전부 따라온다(연구 §3-3).

### - [ ] Step 5 — 저장 검증 (**이 계획에서 새 코드의 절반**)

`Save()`(:1277)의 기존 검증 뒤에 붙인다. **음악이 공짜로 보장하던 것을 여기서 강제한다.**

| # | 검사 | 처리 | 근거 |
|---|---|---|---|
| 1 | 마지막 엔트리 `template.Attacker != Player` | **중단** | R-T13 / 결정 6 |
| 2 | 인접 엔트리 입력 간격 < `minEntryGap` | **중단** | R-T11 — §3·§4·R-R10 분석 전체의 전제 |
| 3 | `exposure`가 커서 **큐에 2개 넘게 오른다** | **중단** | R-T12 |
| 4 | `clip.length`가 마디 정수배가 아니다 | 경고 | R-T10 / R-L3 |
| 5 | 사슬 안에 `Attacker` 혼재 | 경고 | 기존 규칙(§11-5), Loop에서 더 중요 |
| 6 | 빈 채보 | 중단 | 기존 |

**2번의 식** — `minEntryGap`은 상수 0.4초가 아니라 **런타임 노브에서 유도**해야 한다:
```
필요 간격 ≥ handoverIgnoreDuration + (판정 여유)     // §3
그리고    ≥ exposure − goodWindow                    // 큐에 최대 1개 (R-R10)
```
**⚠ 씬 값을 툴이 모른다.** `goodWindow`·`handoverIgnoreDuration`은 씬 `PatternHandler`의 직렬화 값이고 **§4가 그 의존을 일부러 없앴다**(툴이 씬을 요구하지 않는다). → **툴에 같은 기본값을 복제해 두고 "런타임 값은 씬이 정한다"를 명시**한다. `chainKillRatio`가 이미 그 방식이다(:91~95).

**3번의 식** — 인접 세 엔트리 `k, k+1, k+2`에 대해
`onset_{k+2,0} − exposure_{k+2,0} > lastNode_k + goodWindow` 여야 한다(아니면 k가 끝나기 전에 셋이 큐에 있다).

- **⚠ 2·3번을 경고가 아니라 중단으로 두는 이유**: 어긴 채보는 *조금 이상한* 게 아니라 **취소 경로(Step 4-A)가 1개만 회수하고 나머지를 흘려 적 배정이 영구히 밀린다.** 조용히 잘못된 채보를 쓰는 것보다 낫다는 기존 규율(`spawnTimes == null` 처리)과 같다.

### - [ ] Step 6 — 격자 표시와 요약

- 상단 요약: `패턴 12개 (공격 8 · 방어 4) · 8마디 × 2바퀴 · 최소 간격 2스텝(0.67s)`
- **⚠ `RequiredHits` 표시(:98)를 고친다.** 사슬 전체 재시도로 `chainKillRatio`가 죽은 노브가 됐으므로(R-T14) 지금 표시는 **거짓말이다.** `사슬 3타 — 전부 성공해야 처치` 로 바꾸고, 그 옆에 `실패 시 이 사슬 전체가 다시 나옵니다`를 적는다.
- 사슬을 캔버스에서 **한 덩어리로 묶어 그린다**(재시도 단위이므로). 지금은 목록 뱃지로만 보인다.

### - [ ] Step 7 — 미리듣기 (메트로놈) · **범위 안**

분석이 없어졌으므로 **"이 리듬이 곡과 맞는가"를 귀로 확인해야 한다**(연구 §3-5). 그 확인 수단이 통째로 사라진 채로 저작하는 것이 이 개편의 가장 큰 실무 위험이라 **넣는다.**

- 최소 스펙: **선택한 마디부터 곡 재생 + 엔트리의 온셋마다 클릭**. 믹스를 듣는 게 목적이 아니라 **격자와 음악이 맞는지** 보는 것이다.
- **⚠ 루프 균질성(R-L5)을 확인하는 유일한 수단이기도 하다.** 드리프트가 쌓이면 패턴이 곡의 다른 부분 위에 얹히는데(코드가 못 푸는 제작 요구), **여러 마디에서 같은 리듬을 들어 보는 것**이 그 판단의 전부다. → 재생 시작 마디를 **저작자가 고를 수 있어야 한다**(처음부터만 재생되면 확인이 안 된다).
- **⚠ 에디터 오디오 재생은 공개 API가 없다.** `AudioUtil` 리플렉션(비공개)이나 임시 `AudioSource`가 필요하다 — **깨지기 쉬우므로 실패하면 조용히 비활성**되게 한다(기존 배선 누락 규율). 재생이 안 돼도 나머지 저작은 성립해야 한다.
- **⚠ 클릭은 오디오가 아니라 시각으로도 낼 수 있다.** 재생 위치 커서를 캔버스에 그리는 것만으로도 격자 정합의 절반은 눈에 보인다 — 리플렉션이 막히는 환경의 폴백.
- 나머지 단계와 독립이므로 **구현 순서는 마지막**이지만 **범위에는 들어간다.**

### - [ ] Step 8 — Linear 격리 확인(회귀 방지)

- `OnsetDetector`·`OnsetGrouper`·`OnsetChunkSplitter`·`PatternTemplateLibrary.GetNextTemplate`/`GetRandomTemplate` 호출 지점이 **Linear 분기 안에만** 있는지 확인.
- `ChartGen/Tests`의 기존 코어 유닛테스트가 **한 개도 안 깨져야 한다**(그 셋은 순수 함수라 Loop가 안 건드린다).
- 기존 채보 17개를 열어 **저장 → diff가 비어야 한다**(`authoredWith` 기본값이 `Linear`라 경로가 같다).

### - [ ] Step 9 — 검증(수동)

- [ ] Loop 채보를 굽고 **`StageMode.Loop`로 재생** → 패턴이 박에 맞는다
- [ ] 재시도를 여러 번 해도 박이 유지된다(드리프트 × 격자)
- [ ] 곡 1바퀴를 넘는 채보가 **루프 2회차에서 정상 진행**된다 (R-T15)
- [ ] 인접 스텝에 엔트리 둘을 놓으면 **저장이 막힌다** (R-T11)
- [ ] 노출을 키워 셋이 큐에 오르게 하면 **저장이 막힌다** (R-T12)
- [ ] 마지막을 방어 패턴으로 두면 **저장이 막힌다** (R-T13)
- [ ] 마디 정수배가 아닌 곡에 **경고가 뜬다** (R-T10)
- [ ] BPM을 바꾸면 **배치가 격자를 유지한 채 늘어난다/줄어든다** (연구 §3-3)
- [ ] `authoredWith = Loop`인 채보를 Linear 모드로 열면 **`분석`이 비활성**이다
- [ ] 기존 Linear 채보 17개 열기 → 저장 → **diff 없음** (Step 8)
- [ ] 미리듣기: **중간 마디부터 재생**되고 온셋마다 클릭이 난다 (Step 7)
- [ ] 미리듣기가 실패하는 환경에서도 **저작이 정상 동작**한다(커서만 남는다)

## 확정된 결정

| # | 결정 | 그래서 |
|---|---|---|
| 1 | **등간격 자동 생성** *(시작 스텝, 간격, 템플릿)* | 그룹핑 문제가 **되돌아오지 않는다**. 온셋이 격자 위에 있음과 "노드 수 = 온셋 수"가 **구조적으로 보장**된다. 불규칙 리듬은 행 편집에서 스텝 단위 개별 이동 |
| 2 | **`minEntryGap` 기본값 복제** | 툴이 씬을 안 읽는다(§4가 없앤 의존이 되살아나지 않는다). `chainKillRatio`(:91~95)와 같은 관용구 |
| 3 | **미리듣기 포함**(Step 7) | 분석이 사라진 자리를 메운다. 덤으로 **루프가 균질한지**(R-L5)를 귀로 확인하는 유일한 수단이 된다 |

**⚠ 2번의 대가 — 상수가 두 곳에 산다.** 씬에서 `goodWindow`·`handoverIgnoreDuration`·`exposureDuration`을 바꾸면 **툴의 검사가 조용히 낡는다.** `chainKillRatio`가 이미 그 상태다. 완화는 하나뿐이다:

> 툴의 복제 상수에 **"런타임 값은 씬의 `PatternHandler`가 정한다. 바꾸면 여기도 바꿔라"**를 주석으로 못박고, 검사 메시지에 **어떤 값을 가정했는지 숫자로 찍는다**(`간격 0.33s < 필요 0.40s — goodWindow 0.10 · exposure 0.50 가정`). 저작자가 어긋남을 눈으로 볼 수 있게 하는 것이 유일한 방어다.
