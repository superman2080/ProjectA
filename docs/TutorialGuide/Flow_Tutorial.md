# Flow — 튜토리얼 전체 흐름

`Seq_Tutorial` 저작의 **진실의 원천**이다. 대사·캡션 원문과 순서를 여기서 정하고, 에셋은 이 문서를 옮긴 결과물이다.
설계 근거는 `Plan_TutorialScene.md`(씬·드릴) · `Plan_TutorialGuide.md`(강조·키 입력) · `Plan_TutorialPolish.md`(완성도)에 있다.

---

## 0. 이 튜토리얼이 가르치는 것

**조작 넷이 아니라 규칙 하나다** — *박에 겹쳐 베지 않으면 완전히 소멸하지 않는다*(`Story_Overview.md` §2-1).
드릴 넷은 그 규칙을 손에 붙이는 순서이고, **박의 출처는 여기서 한 글자도 나오지 않는다**(§2-5).

말하는 사람은 둘이고 **역할이 갈린다.**

| | 카시마 (대사창 · 하단 · 이름표 있음) | 안내 (캡션 · 상단 · 이름표 없음) |
|---|---|---|
| 맡는 것 | 태도 · 판단 · 검술의 말 | 조작 · 수치 · 화면 요소의 이름 |
| 예 | *"손이 먼저 기억할 테니까"* | *"숫자키 1~9"* |
| 금지 | 시스템 설명(§0) | 박 · 균열 · 그것들 |

⚠ **둘이 같은 것을 말하면 한쪽이 환경음이 된다.** 겹치면 성질에 맞는 쪽으로 보낸다.

## 1. ⚠ 저작 전에 알아야 할 것 둘 (실측)

### 1-1. 패턴 에셋 이름은 **인덱스** 기준이다 — 점 번호가 아니다
`Pattern(3, 4, 5)`의 `patternDatas`는 인덱스 3·4·5이고, **화면의 점으로는 Point_4 · Point_5 · Point_6**이다(Point_1이 인덱스 0).

| 에셋 이름 | 실제 점 | 쓰는 곳 |
|---|---|---|
| `Pattern(3, 4, 5)` | **4 → 5 → 6** (가로 직선) | 드릴 1 |
| `Pattern(6, 7, 3, 4)` | **7 → 8 → 4 → 5** (꺾임) | 드릴 2 |
| `PatternChain(3, 4)` | 4 → 5 | 드릴 3 (1타) |
| `PatternChain(4, 6)` | 5 → 7 | 드릴 3 (2타) |
| `PatternChain(6, 4)` | 7 → 5 | 드릴 3 (3타) |
| `PatternChain(4)` | 5 | 드릴 3 (4타) |
| `PatternMash(4)` | **5** (정중앙 — 게이지 링이 앉는 자리) | 드릴 4 |

- **`PatternChain(4, 6)`은 더 이상 중복이 아니다.** `Plan_TutorialScene` 4-5의 경고(내용이 `3, 4`와 같다)는 그 뒤 고쳐졌다 — 지금은 `5 → 7`이다.
- **⚠ 사슬 순서는 `(3, 4)` → `(4, 6)` → `(6, 4)` → `(4)`다.** 점으로는 **4→5 · 5→7 · 7→5 · 5**라 **앞 패턴의 끝점이 다음 패턴의 시작점**으로 이어진다 — "하나씩 끊지 말고 한 호흡으로"(19번 대사)가 손에서 실제로 성립하는 이유이고, 순서를 바꾸면 그 연결이 끊긴다.
- ⚠ **첫 드릴의 첫 점은 Point_4다.** 직전 구현이 이름을 점 번호로 읽어 `Point_3` / `nodeIndex = 2`로 배선했다 — **화면에서 강조한 점과 실제로 눌러야 할 점이 달랐다.** 이 문서의 배치가 그것을 고친다.

### 1-2. 캡션은 스스로 기다리지 않는다
`HighlightStep.IsFinished`는 **언제나 true**라, 캡션 셋을 나란히 두면 **한 프레임에 전부 지나가고 마지막 하나만 보인다**(러너는 한 프레임에 최대 64스텝을 넘긴다).
지금 배선된 첫 두 캡션(*"아홉 개의 점"* · *"숫자키…"*)은 **한 번도 화면에 나온 적이 없다.**

→ **캡션 뒤에는 반드시 '기다리는 것'이 온다.** 셋 중 하나다:
1. `WaitStep`(읽는 시간) — 뒤가 또 캡션일 때
2. `WaitInputStep`(직접 해 보기)
3. `PatternDrillStep`(드릴 — 캡션이 드릴 내내 떠 있는다)

**읽는 시간의 기준: 한 줄 2.5초 · 두 줄 3.5초.** (대사창은 타자기가 속도를 정하지만 캡션은 즉시 뜬다.)

## 2. 전체 흐름

여섯 국면이다. **국면마다 새로 배우는 것이 정확히 하나**이고, 앞 국면에서 배운 것은 다시 설명하지 않는다.

| 국면 | 새로 배우는 것 | 무대 |
|---|---|---|
| A. 만남 | (없음 — 태도) | 시작 지점 |
| B. 조작 | 점을 누른다 · **키보드와 마우스 둘 다** | 시작 지점 |
| C. 획 | 순서대로 잇는다 · 가이드라인 | Tatami1 |
| D. 박 | **링이 노브에 겹치는 순간** · 실패하면 남는다 | Tatami2 |
| E. 연결 | 한 호흡으로 넷 · 통과 노드 | Tatami3 |
| F. 연타 | 순서가 없는 것 · 세는 것이 아니라 미는 것 | Tatami4 |

⚠ **국면 F만 이동이 설명보다 먼저다.** 연타는 규칙이 앞의 넷과 정반대(순서 없음·타이밍 없음)라, 표적 앞에 선 채로 들어야 무엇에 대한 말인지가 붙는다.
나머지 넷은 달려가는 2초가 곧 다음 대사를 듣는 시간이다.

## 5. 하지 않는 것
- **스킵 버튼 · 진행도 표시** — 게임이 자기 구조를 설명하는 부류(§0). 재연습은 `Retry` 자리가 맡는다.
- **실패마다 뜨는 격려·힌트** — 반복되면 환경음이 된다.
- **회피(Space) 교육** — 이 씬엔 `DodgeDirector`가 없어 눌러 볼 상황 자체가 없다. **1스테이지에서 처음 만난다.**
- **점수·콤보 설명** — HUD가 이미 떠 있고, 튜토리얼의 규칙 하나에 섞으면 무엇을 배웠는지가 흐려진다.
- **박의 출처** — 트루 엔딩까지 소리로만 회수된다(§2-5).
