# Guide_PatternChartTool.md — 채보 에디터(Pattern Chart Tool) 사용법

이 문서는 `Tools/Pattern Chart Tool`의 실사용 가이드입니다. 설계 배경은 `Research_ChartGen.md`, 구현 계획은 `Plan_ChartGen.md`를 참고하세요.

**툴은 창 상단 토글로 저작 방식이 갈립니다.** 두 방식은 같은 중간 표현과 같은 저장 경로를 쓰고, **그것을 채우는 방법**만 다릅니다.

| 방식 | 온셋이 어디서 오나 | 언제 쓰나 |
|---|---|---|
| **Linear**(아래 A~C 절) | 음원 **온셋 분석** | 곡 길이대로 한 번 재생하는 채보(`StageMode.Linear`) |
| **Loop**(맨 아래 D 절) | 저작자가 **마디 격자**에 직접 놓는다 | 곡이 루프하며 **모든 패턴을 해결해야 끝나는** 채보(`StageMode.Loop`, 스토리 모드의 기본) |

> **⚠ Loop 채보를 Linear 모드에서 `분석`으로 덮으면 저작이 통째로 날아갑니다.** 툴이 그 버튼을 비활성화해 막습니다(`SongChart.authoredWith`로 판단).

## 사전 준비물

1. **패턴 템플릿**: `Assets/Patterns/Templates` 폴더 아래에 노드 개수별 `Pattern` SO 에셋을 미리 만들어 둡니다.
   - `Pattern` 에셋은 `Assets → Create → Scriptable Objects → Pattern`으로 생성
   - `PatternData` 배열의 각 항목은 `index`(0~8, 3x3 격자 위치)만 지정하면 됩니다 — 노출시간/타이밍은 여기서 설정하지 않습니다(곡이 소유)
   - 같은 노드 개수를 가진 템플릿을 여러 개 만들어두면 굽는 에디터가 그중 하나를 랜덤으로 배정합니다
   - 예시 템플릿 3종(`Pattern_1Node_Center`, `Pattern_2Node_Diagonal`, `Pattern_3Node_LShape`)이 이미 폴더에 들어있습니다 — 필요에 맞게 수정하거나 삭제하고 원하는 모양으로 다시 만드세요
2. **씬의 `PatternHandler`**: 낙하 소요시간(`ComputeFallDuration`) 계산은 Point 위치, 캔버스 화면 경계 등 씬 레이아웃에 의존하므로, 현재 씬에 있는 실제 `PatternHandler` 컴포넌트를 굽는 에디터에 참조로 지정해야 합니다.
3. **오디오 클립**: 채보할 곡의 `AudioClip`을 프로젝트에 임포트해둡니다.

## 툴 열기

메뉴에서 `Tools → Pattern Chart Tool`을 선택합니다.

## 워크플로우 A — 새 곡 채보하기

1. **음원 / 대상 SongChart** 영역에서 `Audio Clip`에 채보할 곡을 지정합니다. `기존 SongChart (불러오기용)`은 비워둡니다.
2. **씬 PatternHandler 참조**에 씬의 `PatternHandler`를 드래그합니다. (지정 전까지 저장 버튼이 비활성화됩니다.)
3. **분석 파라미터**를 설정합니다.
   - `RMS 임계값`: 온셋(비트) 감지 민감도. 값이 낮을수록 더 작은 소리 변화도 온셋으로 잡습니다.
   - `윈도우 크기(샘플)`: RMS 계산 단위. 기본 1024(약 23ms @44.1kHz).
   - `기본 노출시간(초)`: 새로 분석된 그룹의 각 노드에 기본으로 채워질 노출시간.
4. **BPM / 비트 그리드**를 설정합니다.
   - `BPM`: 곡의 정확한 BPM을 직접 입력합니다(자동 감지 없음 — 리듬게임 채보 관행상 BPM/오프셋은 항상 수동 입력).
   - `Beat Offset(초)`: 곡에서 첫 박이 시작하는 정확한 시각(초).
   - `Level (1~30)`: 채보 밀도. 1~10=4분음표 그리드, 11~20=8분음표, 21~30=16분음표 (구간 경계는 `Tier1 Max`/`Tier2 Max`로 조정 가능).
   - `최대 그룹 갭(그리드 스텝)`: 몇 그리드 칸까지 비어야 그룹을 나눌지(기본 1칸).
5. **"분석 (새로 만들기)"** 버튼을 누릅니다. 파형과 함께 그룹 목록이 생성됩니다.
6. 상단 **노드 개수 불일치 배너**를 확인합니다. 빨간색이면 특정 그룹에 배정할 템플릿이 없다는 뜻입니다 — 목록에서 빨간 항목("템플릿 없음")을 찾아, 해당 개수의 템플릿을 새로 만들고 "재배정"을 누르거나, 이미 있는 다른 템플릿을 수동으로 배정하세요.
7. 그룹별로 필요하면:
   - **재배정**: 같은 노드 개수의 다른 템플릿으로 랜덤 교체
   - **수동 교체**: 원하는 템플릿을 직접 지정(노드 개수가 다르면 거부됨)
   - **노드별 노출시간**: 값을 바꾸면 그 노드의 스폰 시각 미리보기가 즉시 갱신됨
8. 모든 그룹에 템플릿이 배정되면 **"저장 (새 SongChart 생성)"**을 눌러 저장 경로를 지정합니다.

## 워크플로우 B — 이미 구운 SongChart 다시 편집하기

1. **기존 SongChart**에 수정할 `SongChart` 에셋을 지정합니다.
2. **"불러오기"** 버튼을 누르면 그 안의 그룹들과 `level`/`bpm`/`beatOffset`이 그대로 불러와집니다.
3. 원하는 그룹만 재배정/수동교체/노출시간 수정을 하고 — **다른 그룹은 전혀 건드리지 않아도 됩니다.**
4. **"저장 (기존 SongChart 덮어쓰기)"**을 누르면 같은 에셋에 덮어써집니다(다른 곳에서 참조 중이어도 끊기지 않음).

> 노출시간만 바꾸고 싶을 때: 위 워크플로우로 불러온 뒤 노출시간만 수정하고 저장하면, 온셋(입력 판정 시각)은 그대로 유지된 채 스폰 시각만 다시 계산되어 저장됩니다. 이게 "재굽기"입니다.

> 주의: `Level`/`BPM`/`Beat Offset`/`RMS 임계값` 등을 바꾼 뒤 **"분석"을 다시 누르지 않으면** 그룹 구조 자체는 갱신되지 않습니다. 그룹 구조를 다시 만들고 싶으면(밀도를 실제로 바꾸고 싶으면) 반드시 "분석"을 재실행하세요 — 이 경우 그룹별로 해둔 수동 편집은 초기화됩니다.

## 곡 재생하기 (`ChartPlayer`)

1. 씬에 빈 GameObject를 만들고 `ChartPlayer` 컴포넌트를 추가합니다.
2. `Song Chart`에 구운 SongChart 에셋을, `Audio Source`에 재생용 `AudioSource`를, `Pattern Handler`에 씬의 `PatternHandler`를 연결합니다.
3. Play 하면 오디오가 재생되며, 각 그룹의 스폰 시각에 맞춰 자동으로 `PatternHandler.SetPattern`이 호출되어 곡 전체가 순차 재생됩니다.

## 알려진 제약

- **BPM 자동 감지 없음**: 항상 수동 입력. 파형 위 비트 그리드 세로선이 실제 비트와 맞는지 육안으로 확인하고 안 맞으면 BPM/오프셋을 조정하세요.
- **낙하 스폰 계산은 씬 레이아웃에 의존**: `PatternHandler`의 Point 배치나 캔버스 크기를 바꾸면, 이미 구운 `spawnTimes`가 실제 화면과 안 맞을 수 있습니다 — 이 경우 굽는 에디터에서 "불러오기" 후 다시 "저장"하면 스폰 시각이 새 레이아웃 기준으로 재계산됩니다.
- **곡 시작부 리드인 필요**: 첫 그룹의 온셋이 곡 맨 앞부분(0초 근처)에 있으면, 노출시간에 따라 스폰 시각이 음수(오디오 시작 이전)로 계산될 수 있습니다. 실제 채보 시 곡 맨 앞에 약간의 무음 리드인을 두는 것을 권장합니다.
- **`PatternHandler.SetPattern`이 `Time.time` 기준으로 스케줄링**하므로, `AudioSource.time`과 완전히 프레임 단위로 동기화되지는 않습니다(참고용 오차 범위 — Plan 문서 Step 7 참고).
- 같은 템플릿이 곡 안에서 시간이 겹치도록(동시에) 재생되면 안 됩니다 — `ChartPlayer`는 항상 그룹을 순차 재생하므로 정상 사용 시 문제 없습니다.

## D절 — Loop 모드(마디 격자 저작)

> 배경: `CLAUDE.md` §16(진행과 재시도) · `docs/LoopChartTool/`
>
> **왜 분석이 아닌가**: `StageMode.Loop`에서는 공격 패턴을 실패할 때마다 채보 시계가 **박의 정수배로** 뒤로 밀립니다. 그 드리프트가 온셋과 음악 트랜지언트의 대응을 지우므로, "온셋을 트랜지언트에서 뽑는다"는 전제 자체가 무너집니다. 대신 **격자 위에만 놓으면 밀려도 여전히 격자 위에 앉습니다.**

### D-1. 설정

1. 상단 **저작 방식**을 `Loop (마디 격자)`로 바꿉니다.
2. `Audio Clip`을 지정합니다.
3. **BPM / 비트 그리드**에서 `BPM`·`Beat Offset`·**`마디당 박 수`**·**`박당 스텝 수`**를 채웁니다.
   - `박당 스텝 수`가 격자 해상도입니다(2 = 8분음표). **레벨에서 파생되지 않습니다** — 저작자가 직접 고릅니다.
   - 아래에 **스텝 간격(ms)** 이 표시됩니다.
4. `격자 세우기 (새로 만들기)`를 누릅니다. 곡 길이에서 마디 수가 유도됩니다.

### D-2. 배치

- **놓을 패턴**에 템플릿을 지정하거나, 패턴 풀에 넣어 둔 것을 아래 버튼 줄에서 고릅니다(풀은 Loop에서 **팔레트**로 쓰입니다).
- **노드 간격**은 등간격 배치의 스텝 간격입니다. 클릭하면 `시작 스텝 + i × 간격`으로 온셋이 자동 생성되므로 **"노드 수 = 온셋 수"가 어긋날 수 없습니다.**
- 캔버스는 **가로 = 스텝, 세로 = 마디 한 줄**입니다(한 줄로 늘이면 가로 스크롤만 남습니다).
  - 빈 자리를 클릭 → 배치 / 엔트리를 클릭 → 선택 / 선택한 채로 드래그 → 이동 / 아래 `←` `→` `삭제`
  - 굵은 선 = 마디, 중간 선 = 박, 얇은 선 = 스텝. **주황 세로선 = 곡 1바퀴가 끝나는 지점**입니다.
  - **마디 수는 곡 길이를 넘겨도 됩니다** — 루프 2~3바퀴를 쓰는 채보가 정상입니다.
- **불규칙 리듬**은 엔트리 행의 `노드 i 스텝` 필드로 만듭니다. **값이 스텝이라 격자를 벗어날 수 없습니다** — 초를 직접 고치면 다음 갱신에서 덮입니다.
- **연타**는 온셋이 `창 시작 스텝`·`창 끝 스텝` 둘뿐입니다(`연타 창` 필드로 길이를 정합니다).
- **BPM·오프셋·해상도를 나중에 고쳐도 배치가 격자를 유지합니다** — 시각만 늘어나거나 줄어듭니다.

### D-3. 미리듣기

`미리듣기 시작 마디`를 정하고 `재생`을 누르면 그 마디부터 곡이 흐르고 캔버스에 **재생 커서**가 지나갑니다.

- **여러 마디에서 같은 리듬을 들어 보는 것이 루프가 균질한지 판단하는 전부입니다** — 시작 마디를 옮겨 가며 확인하세요.
- ⚠ **온셋마다 클릭은 나지 않습니다.** 에디터의 미리듣기 채널이 하나뿐이라 클릭이 곡을 잘라 먹습니다.
- ⚠ 에디터 오디오 재생은 공개 API가 없어, 리플렉션이 막히는 환경에서는 **조용히 비활성되고 커서만 남습니다**(저작은 그대로 됩니다).

### D-4. 저장이 막는 것 (두 모드 공통)

지금까지 음악이 공짜로 보장해 주던 것들이라, 격자 저작에서는 직접 지켜야 합니다.

| 검사 | 처리 |
|---|---|
| 빈 채보 | **중단** |
| **마지막 엔트리가 통과 패턴**(`Attacker.Enemy` 또는 상호 공격) | **중단** — 실패해도 소비되어 마무리 실루엣 없이 스테이지가 끝납니다 |
| 인접 엔트리 **입력 간격**이 필요치보다 좁다 | Loop **중단** / Linear 경고 — 승계 직후 입력이 삼켜지고, 재시도 취소가 패턴 하나를 흘려 적 배정이 영구히 밀립니다 |
| 노출이 커서 **큐에 셋이 오른다** | Loop **중단** / Linear 경고 — 같은 이유 |
| 곡 길이가 **마디의 정수배가 아니다** | 경고 — 루프마다 음악이 격자에서 밀리고 바퀴마다 누적됩니다. 압축 포맷의 패딩이 원인일 수 있으니 PCM으로 확인하세요 |
| 스폰 시각이 음수 | 경고 — 노출시간이 온셋보다 깁니다 |

> **⚠ 간격·큐 깊이는 Linear 채보의 저장을 막지 않습니다.** 온셋 분석은 그 값을 지킨 적이 없어(0.25초 간격이 흔합니다) 막으면 기존 채보를 열어 고칠 수조차 없게 됩니다 — 대신 경고만 찍습니다. 그 채보를 `StageMode.Loop`로 재생할 계획이면 경고를 실제 결함으로 읽으세요.
>
> **⚠ 필요 간격은 툴이 가정한 값에서 나옵니다.** `goodWindow`·승계 무시 구간은 씬 `PatternHandler`의 직렬화 값이고 툴은 씬을 읽지 않으므로, **같은 기본값을 복제해 두고 검사 메시지에 가정한 숫자를 찍습니다.** 씬에서 그 값을 바꿨다면 메시지의 숫자와 견줘 보세요.

### D-5. 엔트리 행에서 읽는 것

- **`재시도`** / **`통과`** 뱃지 — 실패했을 때 그 엔트리가 다시 나오는지, 피격하고 넘어가는지.
- **`사슬 N/M · 전부 성공해야 처치`** — 사슬은 **재시도 단위**입니다. 공격 타를 실패하면 사슬 전체가 처음부터 다시 나옵니다.
- 상단 요약 한 줄 — 패턴 수 · 재시도/통과 · 마지막 판정 · 꼬리 · 최소 간격 · 마디 수.
