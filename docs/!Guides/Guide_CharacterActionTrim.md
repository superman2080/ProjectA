# Guide — 패턴 액션 저작 (`Tools/Animation Clip Trimmer`)

패턴 하나의 **전투 액션 짝**(플레이어 + 적)을 함께 저작하는 툴. 창 제목은 `Pattern Action Editor`다.

저작 단위가 클립 하나가 아니라 **패턴 하나**인 이유: 확인해야 하는 것이 "칼이 적에 닿는가 / 임팩트 순간 적 포즈가 말이 되는가"이고, 그 판단은 **두 마크를 되먹임하며 조정해야 수렴**한다.

여기서 저작하는 것은 넷이다 — **트림 마크**(Start/Impact/End) · **추가 칼질**(다중 히트스톱) · **결투 거리**(상수 보정 + 커브) · **칼날 트레일 이벤트**.

---

## 시간축 — `t = 0`이 임팩트다

- 툴의 모든 시각은 **임팩트 기준 상대초**다. `t = 0`이 두 클립의 임팩트 프레임이고, 곧 **칼이 지나가는 순간 = 적이 베어지는 순간**이다.
- 배우마다 길이도 배속도 다르지만 `t = 0`에서는 식에서 소거된다 — **두 임팩트는 정의상 같은 시각이라 서로 맞출 필요가 없다.**
- 반면 **입력 필드는 전부 클립 절대시간**이다(에셋에 들어갈 숫자 그대로). 저장 경로에 변환이 없다.
- 런타임 정렬 식: `임팩트 시각 = Deadline + Pattern.ImpactOffset`. 표적 절단·적 칼·카메라 큐가 **같은 값**을 읽는다.

## 1. 대상 지정

| 항목 | 의미 |
|---|---|
| **Pattern** | 저작할 패턴 에셋(`Assets/04. Datas/Patterns/Templates/*.asset`). 지정하면 역할에 맞는 슬롯이 자동으로 열린다. |
| **역할** (읽기 전용) | `Player` = 플레이어 공격 → 적 사망 / `Enemy` = 적 공격 → 플레이어 패링. `Pattern.attacker`가 정한다. |
| **적 보조 슬롯** | 적 한 명의 **다른 시각 구간**이라 배우를 늘리지 않고 슬롯만 갈아 낀다. `Feint`(표적이 된 순간~임팩트) / `Hit`(맞았는데 안 죽음 — 사슬 중간) / `Parry`(막아냄). |
| **플레이어 / 적 프리팹** | 프리뷰용 리그. 드래그로 회전, 휠로 줌. |

열리는 슬롯은 역할이 정한다:

| 역할 | 플레이어 | 적 |
|---|---|---|
| `Attacker.Player` | `playerAttack` | `enemyDeath` (+ 보조 `enemyFeint`/`enemyHit`/`enemyParry`) |
| `Attacker.Enemy` | `playerParry` | `enemyAttack` (+ 보조 `enemyHit`/`enemyParry`) |

## 2. 트림 마크 찍기

`▶ Play` / `◀ Frame` / `Frame ▶` / `t = 0`으로 이송하며 배우 블록에서 찍는다.

- **Mark Start** — 휘두름 시작 직전(준비 자세 제거).
- **Mark Impact** — **칼날이 표적을 통과하는 바로 그 프레임.** 상태 박스가 `✦ IMPACT`로 바뀐다.
- **Mark End** — 마무리 동작 중 잔여로 남길 만큼까지.

판단 보조:
- 상태 박스의 **칼–적 거리**: 음수면 `▶ 관통 (베고 있음)`, 양수면 `▶ 떨어짐 (안 닿음)`. `t = 0`에서 관통이면 초록, 떨어져 있으면 주황이다.
- 타임라인 마커: 초록 = Start / **시안 = Impact** / 빨강 = End.
- Impact가 Start~End 밖이면 경고가 뜨고, 저장 시 구간 안으로 클램프된다.

**슬롯별 임팩트 규칙이 다르다:**

| 슬롯 | ImpactTime |
|---|---|
| `playerAttack` / `playerParry` / `enemyAttack` | 칼날이 지나가는 프레임에 찍는다. |
| `enemyDeath` | **트림 시작 근처**에 찍는다. 처치 확정~임팩트가 0.1초 남짓이라 뒤에 찍으면 쓰러지는 속도부터 빨라진다. |
| `enemyFeint` | **찍지 않는다.** 닿지 않는 동작이라 트림 끝이 임팩트에 붙는 것이 기본이다. 트림 **0.8초 이하** 권장. |
| `enemyHit` / `enemyParry` | **찍지 않는다.** 맞는 순간이 곧 시작이라 `t = 0`이 클립 시작이 된다. 트림 **0.5초 이하** 권장. |

## 3. 추가 칼질 (다중 히트스톱)

여러 번 베는 클립은 칼질마다 화면이 멈춘다. **`Mark Impact`는 언제나 '마지막 베기'**이고, 그 **이전**의 칼질을 `+ Mark Extra`로 찍는다.

- 타임라인에 `◆ N타` 배지로 보이고, 그 프레임에 서 있으면 상태 박스가 파랗게 바뀐다.
- **정지 예산**(정지 횟수 × `hitStopDuration`)이 표시된다. **0.3초를 넘으면 경고** — 엔트리 간 최소 입력 간격이 0.4초라 그 위로는 대부분의 채보에서 창을 넘긴다.
- 마지막 베기 **이후**의 마크는 런타임·툴 양쪽에서 버린다(남기면 몸이 갈라진 뒤에 화면이 멈춘다).

## 4. 결투 거리

### 4-1. 기준 거리 + 상수 보정

| 항목 | 의미 |
|---|---|
| **기준 결투 거리** | 씬에 `EnemyDirector`가 있으면 **결투 앵커에서 자동으로 읽는다**(런타임과 같은 함수). 라벨에 `씬 결투 앵커에서 읽음` / `수동 입력`이 표시된다. |
| **거리 보정 (패턴 저장)** | 이 모션의 리치에 맞춘 ±m. `Pattern.duelDistanceOffset`으로 저장된다. |

### 4-2. 결투 거리 커브 — 패턴 진행 중 간격을 바꾼다

**키 시간 = 임팩트 기준 상대초(0 = 임팩트), 값 = 절대 간격(m).** 타임라인의 `t`와 같은 축이다.

1. `+ 커브 만들기` — **지금 상수 거리와 같은 직선**으로 시작한다(만들자마자 그림이 바뀌지 않게).
2. **결투 거리 커브** 필드를 눌러 Unity 커브 에디터에서 지점을 찍고 끈다. 탄젠트로 변화 방식을 정한다.
3. 스크럽하면 **플레이어가 축을 따라 움직인다**(적은 임팩트 자리에 고정 — 런타임과 같은 모델). 현재 간격이 `간격 t=+0.00s : 1.20m`로 표시되고, 음수면 `(지나침)`이 붙는다.

- **음수 = 지나치기**: 플레이어가 적을 지나쳐 뒤로 나간다. 회전은 안 건드리므로 **등 돌린 채 지나간다**.
- **구동 구간은 플레이어 클립 재생 구간**이다(= 도착 이후). 그 밖은 **끝 키 값으로 홀드**되므로 커브를 클립보다 길게 그려도 앞쪽은 안 보인다.
- **시각은 재생 헤드를 따라간다** — 히트스톱에 같이 얼고, `AttackSpeed` 압축이 걸리면 같이 압축된다.
- **커브를 비우면 예전 상수 경로**(기준 거리 + 거리 보정) 그대로다.
- ⚠ `Attacker.Enemy` 패턴에도 걸 수 있지만 **적 칼은 예약 시점의 자리를 겨냥한다** — 임팩트 시점(`t = 0`) 간격을 저작값과 맞춰 두지 않으면 칼이 빗나간다. 프리뷰가 그 어긋남을 그대로 보여 준다.

### 4-3. 뒤로 빠질 때(백스텝)

지나친 뒤 다음 패턴에서 되돌아오는 구간처럼 **플레이어가 뒤로 이동**하면 `Quickshift` 스테이트의 클립이 `Quickshift_B`로 교체된다(새 스테이트 없음). 뒤로 갈 때는 Sprint 분기를 타지 않는다.

**씬 배선 2개가 필요하다**(안 하면 조용히 예전 동작):
- `CharacterActionPlayer.quickshiftBackClip` ← `Assets/05. Animations/Clip/Move/Quickshift_B.anim`
- `PlayerCombatMover.actionPlayer` ← 같은 오브젝트의 `CharacterActionPlayer` (거리 커브 구동의 시간 원점)

⚠ 교체의 키는 `CharacterActionPlayer.quickshiftClip`이다 — 애니메이터 `Quickshift` 스테이트에 **실제로 물린 그 클립**이어야 교체가 먹는다.

## 5. 칼날 트레일 이벤트

`Write StartSwordTrail(Start) / StopSwordTrail(End) to Clip` — 플레이어 클립에 트레일 on/off **애니메이션 이벤트**를 트림 구간에 써 넣는다. 코드는 관여하지 않는다(이벤트가 켜고 끈다).

## 6. 저장

`▶ Apply to Pattern (모든 슬롯 + 거리 보정)` — 세 슬롯 · 추가 칼질 · 거리 보정 · 거리 커브를 **한 번에** 기록한다(한쪽만 저장돼 짝이 어긋난 상태를 만들지 않는다).

- 아래 줄이 `✔ 저장됨` / `● 저장 전 — 창의 값이 에셋과 다릅니다`로 동기 상태를 보여 준다.
- 저장 직후 에셋을 다시 읽어 창과 대조한다(라운드트립 검증). 어긋나면 에러가 뜬다.
- Play 모드에서 확인하고 미세 조정한다. 디버그 오토퍼펙트로 연속 재생하면 편하다. `SliceTargetDirector.drawGizmos`를 켜면 표적 도착 지점과 칼 궤적을 씬 뷰에서 대조할 수 있다.

## 튜닝 지침

- **짧을수록 안전**: 트림이 짧을수록 촘촘한 구간에서 잘릴 위험이 낮다. 단 "휘두름 핵심"은 남긴다.
- **임팩트 이후 잔여도 짧게**: 임팩트가 정렬 기준이라 그 뒤가 길수록 액션 종료(`actionEndTime`)가 밀려 다음 공격의 크로스페이드에 끊긴다. "칼을 거두는 낌새" 정도만.
- 긴 클립(1.2~1.8초)을 촘촘한 구간에 쓰면 트림해도 배속 상한(`maxAttackSpeed`, 기본 2.5)에 걸릴 수 있다. ⑴ 트림을 더 줄이거나 ⑵ 그 구간에 더 짧은 클립을 배정한다.
- `maxAttackSpeed` 상향은 최후의 수단 — 모든 액션의 배속감에 영향을 준다.
- 저작 배속 기준으로 보인다. 런타임은 채보 간격과 입력 시각에 따라 압축되지만 **그때도 임팩트 프레임은 같은 시각**이다.
