- [ ] (선택) `Idle`을 `Run` 대신 정지 포즈로 — 지금은 링에서 제자리 달리기처럼 보인다

> **`Evade`를 작게 유지하는 이유 셋** (클립을 다시 손볼 때 참고):
> 1. **막을 칼이 없다.** 플레이어가 실패하면 스윙이 취소된다(`HandleJudgeTargetFirstMiss` — `hasPending = false`).
>    크게 피하면 허공을 피하는 게 티 난다. 같은 이유로 **패링/막기는 쓸 수 없다**(접촉이 전제다).
> 2. **실패는 플레이어 것이어야 한다.** 화려한 회피는 "적이 반응했다"로 읽혀 내 실수가 적의 실력으로 번역된다.
>    실패가 멋있어 보이면 벌로 안 읽힌다.
> 3. **패링은 `Attacker.Enemy`의 어휘로 남긴다.** 지금 반응 어휘가 대칭이다 —
>    `적 공격 + 플레이어 성공 → KnockBack` / `플레이어 공격 + 플레이어 실패 → Evade`.
>    여기 막기를 섞으면 "적이 막는 그림"이 양쪽 역할에 다 나와 화면으로 `attacker`를 구분할 수 없게 된다.
>
> 패턴 간격 0.4초라 긴 회피는 다음 패턴에 잡아먹혀 어차피 안 보인다.
> 회피를 제대로 살리고 싶으면 **실패 시 스윙을 취소하지 말고 헛치게** 하는 방법이 있지만,
> 헛스윙이 시간을 먹어 다음 패턴과 부딪히므로 별도 판단이 필요하다.

## 3단계 · 패턴 클립 오서링

대상: `Assets/04. Datas/Patterns/Templates/` 10종
툴: `Tools > Animation Clip Trimmer` (창 이름은 **Pattern Action Editor** — 이제 클립 하나가 아니라 **짝**을 편집한다)

### 먼저 패턴의 `attacker`를 정한다

**패턴 인스펙터 맨 위 `attacker`가 나머지를 전부 결정한다.** 한 패턴은 한 역할만 갖는다 —
양쪽이 필요하면 패턴 에셋을 복제한다.

| `attacker` | 살아 있는 슬롯 | 인스펙터·트리머에 보이는 것 |
|---|---|---|
| `Player` (무방비 적을 벤다) | `playerAttack` + `enemyDeath` | 이 둘만 |
| `Enemy` (적 공격을 패링) | `enemyAttack` + `playerParry` | 이 둘만 |

나머지 슬롯은 **인스펙터가 접이식으로 내려버린다.** 값이 남아 있으면 접이식이 자동으로 펼쳐지고
경고가 뜬다 — 그게 이관 찌꺼기를 찾는 자리다.

### 툴은 **짝 단위**로 연다 (슬롯 하나씩이 아니다)

`Pattern`을 지정하면 `attacker`가 짝을 정하고 **두 배우 블록이 동시에 열린다.**
칼이 적에 닿는지는 두 마크를 되먹임하며 조정해야 수렴하므로, 하나씩 열어 찍는 방식으로는 안 된다.

```
Pattern [Pattern(4, 1)]     역할: Player — 플레이어 공격 → 적 사망
플레이어 프리팹 [__]  적 프리팹 [__]
기준 결투 거리 [2.0]  거리 보정 [+0.15]   → 실제 배치 거리 2.15m
☑ 루트 위치 고정

┌──── 합주 프리뷰 (두 배우) ────┐
└──────────────────────────────┘
  ✦ IMPACT   칼–적 거리 -0.040m ▶ 관통 (베고 있음)

  t = +0.000s (impact 기준, 30fps)
  ▶ Play  ◀ Frame  Frame ▶  t=0
  [──●──┃──────]   ┃ = t0(노랑) · 초록/빨강 = 플레이어 Start/End · 파랑/보라 = 적

┌ 플레이어 — playerAttack ┐   ┌ 적 — enemyDeath ┐
│ Clip / Start / Impact / End │   │ Clip / Start / Impact / End │
└──────────────────────────┘   └────────────────┘

[ ▶ Apply to Pattern (두 배우 + 거리 보정) ]   ✔ 저장됨
```

**핵심 규칙 넷:**

1. **`t = 0`이 임팩트다** — 두 클립이 각자의 임팩트 프레임에 선다. 여기가 칼이 지나가는 순간이고,
   **배속이 서로 달라도 이 지점은 정확하다**(식에서 소거된다).
2. **`칼–적 거리`가 판단 기준이다** — `t=0`에서 **음수(관통)여야 벤 것**이다. 각도를 눈으로 보는 것보다 확실하다.
3. **마크 필드는 클립 시간**이다 — 패턴 인스펙터에 찍히는 숫자와 같으므로 눈으로 대조된다.
4. **`Mark Impact`를 누르면 슬라이더가 t=0으로 간다** — 임팩트가 원점의 정의라 당연한 결과다.

| 배우 | `attacker == Player` | `attacker == Enemy` |
|---|---|---|
| 플레이어 | `playerAttack` | `playerParry` |
| 적 | `enemyDeath` | `enemyAttack` |

> **`거리 보정`도 여기서 저작한다.** 모션마다 리치가 다르므로 거리는 저작 데이터다 —
> 프리뷰 노브로만 두면 "툴에선 닿는데 게임에선 안 닿는" 거짓 확인이 된다.
> **기준 결투 거리는 4단계에서 잡은 씬 앵커 값**을 넣고, 보정만 패턴에 저장된다.
> 슬라이서 휴머노이드 모드도 같은 식을 쓴다.
>
> 레거시 슬롯(`successAnimationClip`)은 이 툴에서 빠졌다. 이관이 끝났고 8단계 제거 대상이라,
> 짝 저작 툴에 섞으면 "어느 게 진짜냐"가 다시 생긴다. 필요하면 패턴 인스펙터에서 고친다.

> **구 필드 이관은 끝났다** — 템플릿 10종 전부 `playerAttack`에 클립·트림·임팩트가 들어 있다.
> 일회성 도구(`Tools > Pattern > 구 성공 클립 → PlayerAttack 이관`)는 제거됐다.

### 속도감 손잡이 (여기가 체감을 정한다)

- [ ] **`cruiseSpeed`**(4.5 m/s) — **플레이어의 목표 이동 속도.** 다음 표적까지의 거리를 이 값으로
      역산해 고른다. 창(음악)은 못 바꾸므로 **이 값이 곧 체감 속도다.** 올리면 더 먼 적을 고른다
- [ ] **`playerShare`**(0.85) — 만나는 지점의 플레이어 몫. 8:2 남짓.
      **1로 두지 말 것** — 적이 정지 표적으로 읽힌다. 한 걸음이라도 마중 나와야 교전으로 보인다
- [ ] **`minTargetDistance`**(2m) — 너무 가까운 적만 고르면 제자리 난타가 된다

> **이동 모델**: 무대는 월드 원점에 고정된 원이고 적은 그 **안**에 흩어져 선다.

> 그래서 곡이 빨라지면 이동도 촘촘해지고, **체감 속도는 `cruiseSpeed`로 일정하게 유지된다.**
> 스폰은 **화면 밖에서 즉시** 일어난다(걸어 들어오지 않는다).
> 계산은 `EnemyDirector`가 하고(`OnDuelScheduled`), `PlayerCombatMover`는 자기 몫만 옮긴다.

## 4-5단계 · 채보 없이 패턴 하나만 시험하기

**채보를 손대기 전에** 패턴 하나가 제대로 도는지 확인하는 경로다. 재생 중에 인스펙터 우클릭 메뉴로 한다.

```
1. ▶ 재생
2. EnemyDirector  우클릭 → Debug: Prepare Stage      ← 적을 링에 세운다
3. PatternHandler 우클릭 → Debug: Set Test Pattern   ← 패턴 투입
4. F1/F2/F3 로 노드를 강제 입력 (Perfect/Good/Miss)
```

**2번을 빼먹으면 적이 하나도 없어 전투 연출이 통째로 무연출이 된다.** 정상 재생에서는
`ChartPlayer`가 카운트다운에서 무대를 세우지만 디버그 투입 경로에는 그게 없다.

| 인스펙터 항목 | 어디 | 용도 |
|---|---|---|
| `debugTestPattern` | `PatternHandler` | 시험할 패턴 |
| `debugLeadTime` / `debugNodeInterval` | `PatternHandler` | 첫 노드까지 여유 / 노드 간격(기본 1.0 / 0.4초) |
| `debugInputTimes` | `PatternHandler` | **비워 두면 위 두 값으로 자동 생성.** 특정 리듬을 시험할 때만 채운다 |
| `debugInputEnabled` + F1/F2/F3 | `PatternHandler` | 강제 입력 마스터 스위치 |
| `debugAutoPerfect` | `PatternHandler` | 오토플레이 — 손 안 대고 연출만 볼 때 |
| **`debugCue`** | `EnemyDirector` | **채보 없이 쓸 전투 지시.** `killOnSuccess`를 켜야 처치·절단이 나온다 |

> `attacker`와 `impactOffset`은 **패턴이 소유**하므로 디버그에서도 그대로 동작한다.
> 채보 cue에 남은 것은 `killOnSuccess`·`projectile` 둘뿐이고, 그 둘을 `debugCue`가 대신한다.
>
> `debugCue`는 **채보 cue가 없을 때만** 쓰인다 — 정상 재생에서는 `ChartPlayer`가 항상 밀어 넣으므로
> 이 값이 실제 플레이에 새어 들어갈 일은 없다.

## 5단계 · 채보 저작

- [ ] `Tools > Pattern Chart Tool` → 기존 SongChart 열어 **"전투" 접이식**에 값 입력
  - `성공 시 처치` — 이 공격 성공 = 현재 상대 처치 + 다음 적으로 전환
  - `원거리 오브젝트` — 필요 시 SliceSet

> **"현재 상대"가 정해지는 시점을 알아 두면 튜닝이 쉬워진다.**
> 상대는 큐 투입이 아니라 **그 패턴이 판정 대상이 되는 순간**에 배정된다(`BindReservation`).
> 큐 시점에는 이전 패턴의 성패를 몰라 상대를 알 수 없기 때문이다 — 성공하면 죽고 다음 적,
> **실패하면 같은 적과 계속** 싸운다.
>
> 그래서 적에게 주어지는 이동 시간은 "이 패턴이 얼마나 긴가"가 아니라 **배정~임팩트 구간**뿐이다.
> `EnemyDirector`의 `bindToImpactWindow`(기본 0.45초)가 그 값이고,
> 이걸 기준으로 대기석을 미리 들여보낼지(`stagingDistance`) 정한다.
> **적이 제때 못 붙으면 이 둘을 본다.**
>
> 실패 시 적은 `failRetreatDistance`(1.5m)만 물러난다 — 링까지 돌아가지 않는다(교전이 이어지므로).
> 그때 플레이어가 붙는 속도는 `CharacterActionPlayer`의 Quickshift이고 **배속에 상한이 없다**.
> 상세: `docs/OpponentBinding/`

> **`공격 주체` / `임팩트 오프젯`은 여기서 못 바꾼다** — 회색 필드로 값만 보인다.
> 둘 다 **모션의 성질**이라 패턴 에셋이 소유한다(같은 패턴이 엔트리마다 다른 역할·타이밍을 가질 수 없다).
> 바꾸려면 패턴 에셋을 연다.
>
> 특히 `impactOffset`은 **플레이어 칼 · 적 칼 · 시체 교체 · 투사체 · 카메라 큐가 전부 읽는 하나의 값**이다.
> 하나만 옮기고 다른 쪽을 안 옮겨서 칼이 빗나가는 일이 구조적으로 불가능하다.
- [ ] **기존 4종이 값 없이도 안 깨지는지** 열었다 저장해서 확인
- [ ] 1곡을 적 전투로 재저작해 **레퍼런스 채보**로 삼기

> 재분석(re-bake)해도 전투 지시는 **엔트리 인덱스 기준으로 보존**된다.

## 6단계 · 사망 절단 (휴머노이드 모드)

툴: `Tools > Mesh Slice Baker` → 상단 탭 **`휴머노이드`**

### 왜 탭이 둘인가

| 탭 | 대상 | 입력 |
|---|---|---|
| `일반 메쉬` | 정적 프롭(투사체 표적) | 표적 프리팹 + Shape 프리셋/획 |
| `휴머노이드` | 스킨드 캐릭터(적) | **EnemyDefinition** + **Pattern** + 플레이어 프리팹 |

입력이 근본적으로 다르다 — 휴머노이드는 `Pattern`에서 **포즈(`enemyDeath`)와 칼 궤적(`playerAttack`)을 읽는다.**
탭을 바꾸면 프리뷰·획·캐시가 전부 초기화된다(이전 모드 잔여물이 오인을 부르므로 의도된 동작).

### 절차

> 이 모드는 **`attacker == Player`인 패턴에서만** 의미가 있다(적이 베어지는 건 플레이어가 공격자일 때뿐).
> `Enemy` 패턴을 넣으면 툴이 사유를 띄우고 Bake를 막는다.

- [ ] **입력 채우기**
  - `적 정의 (EnemyDefinition)` — **프리팹이 아니라 정의를 넣는다.** 구운 세트가 그 정의의 프리팹에서
    나왔다는 것이 굽는 시점에 보장되고, 결과도 여기로 자동 배선된다
  - `Pattern` — 포즈(`enemyDeath`)와 칼 궤적(`playerAttack`)의 출처. `attacker`가 `Player`여야 한다
  - `자를 렌더러` — 정의의 프리팹에 `SkinnedMeshRenderer`가 여럿이면 팝업이 뜬다
  - `플레이어 프리팹` — 칼 궤적 샘플링용
  - `기준 결투 거리` — 4단계에서 잡은 씬 앵커 거리. **짝 에디터와 같은 값**을 넣는다.
    실제 배치는 여기에 패턴의 `거리 보정`이 더해진 값이고, 툴이 합계를 표시한다
  - `세트 이름` / `출력 경로` / `단면 머티리얼`
- [ ] **`칼 평면 유도` 클릭**
  - `playerAttack`의 임팩트 프레임에서 `add_weapon_r`을 샘플링해 평면을 만든다
  - **법선 = 칼날 장축 × 진행 방향.** 진행 방향은 임팩트 전후 프레임 차분
  - 프리뷰에 **주황색**으로 겹쳐 그려진다(파란색은 확정된 획)
- [ ] **`이 평면 사용` 클릭** — 획 목록에 추가된다. 이후 법선/거리를 손으로 조정할 수 있다
  - 유도 없이 프리뷰에 직접 **좌드래그로 획을 그어도** 된다(Shift = 45° 스냅)
- [ ] **`Preview`** — 조각 목록 확인
  - 조각마다 정점/삼각형/캡 루프/**영향 본 수**가 뜬다
  - **`◀ 루트`** 표시가 붙은 조각이 스킨드로 남아 래그돌 대상이 된다(나머지는 굳어 날아간다)
  - 의도한 조각이 아니면 절단 평면을 조정한다
- [ ] **`Bake`**
  - 산출물은 **시체 프리팹 하나**다(`{세트이름}_Corpse.prefab`) — 적 스켈레톤 사본 + 조각들
  - `SliceSet`이 **`EnemyDefinition.deathSliceSet`에 자동 배선**된다(이미 다른 게 물려 있으면 확인 다이얼로그)
- [ ] **굽고 나면 소스 FBX의 Read/Write를 끈다** — readable 메쉬는 CPU 쪽 사본을 하나 더 들고 있다.
  - `isReadable` 검사는 **베이커 한 곳뿐**(`MeshSliceBaker.cs:75`)이고 런타임 코드에는 없다.
  - 런타임 `BakeMesh`·`MeshCollider`가 쓰는 것은 **구워둔 `Piece_N.asset`**이다.
    이건 `CreateAsset`으로 만든 독립 메쉬라 **임포터 토글 자체가 없고 항상 readable**이다.
  - **다시 구울 때만 켠다.** 꺼져 있으면 툴이 사유를 띄우고 막는다.

### 세트는 적 종류가 소유한다 (패턴에는 없다)

시체 프리팹 안에 **그 적의 스켈레톤 사본**이 들어 있어, 세트는 원리적으로 적 모델을 넘나들 수 없다.

패턴에 두면 축이 어긋난다 — **세트는 패턴이 고르는데 죽는 적은 링에서 정해진다.**
`rosterPool`에 적이 둘 이상이면 적A로 구운 시체가 적B 자리에서 나오고,
리그가 같고 메쉬만 다르면 **본 수가 맞아서 경고도 안 뜬다.**

그래서 프리팹을 소유한 쪽(`EnemyDefinition`)에만 둔다 — 검증으로 막는 대신
**그 상태를 표현 불가능하게** 만든다.

결과: **세트 수 = 적 종류 수**(2~3개). 패턴 수와 무관하니 메쉬 메모리도 프리웜도 문제가 없다.

**대가**: 절단 각도가 적 종류당 하나로 고정된다. 이 적은 항상 같은 방향으로 갈라진다.
각도 다양성이 필요해지면 정의에 세트 배열을 두고 패턴이 인덱스로 고르게 올린다
(전부 같은 프리팹에서 구워지므로 모델 정합성은 유지된다).

> 프리웜은 `EnemyDirector`가 `rosterPool`을 훑는 것으로 끝난다 — 채보를 볼 필요가 없다.

### 시체 소멸 (절단이 아닌 경로)

- [ ] **dissolve 머티리얼** — `Assets/Shaders/Dissolve/Dissolve.shadergraph` 기반으로 `Humanoid_Body_*` 4종 재작성
  - 노출 프로퍼티 이름 확인 후 `EnemyView.dissolveProperty`에 입력(기본 `_Dissolve`)
  - 셀 셰이더(`CelShader`) 룩이 바뀌면 **소멸 순간에만 교체**하는 쪽으로
  - 진행은 `MaterialPropertyBlock`이라 인스턴스별로 따로 사라진다

> 곡이 끝날 때 남은 적은 **베지 않았으므로 갈라지지 않고 소멸**한다. 절단과 다른 경로다.

| 유도된 절단 평면이 엉뚱한 자리 | 위와 같은 원인 — 샘플링이 플레이어를 옮긴 뒤 칼 위치를 읽음 | 코드에서 처리됨(샘플링 후 배치 복원). **이전에 구운 세트는 다시 구울 것** |
| `칼–적 거리`가 `—`로만 나옴 | `add_weapon_r` 아래 렌더러를 못 찾음 | 플레이어 프리팹에 칼이 붙어 있는지 확인. 클립에 무기 본 커브가 없으면 `Tools > Weapon Bone Bake` |
| 툴에선 닿는데 게임에선 안 닿음 | `기준 결투 거리`가 씬 앵커와 다름 | 4단계 값과 맞춘다. 리치 차이는 `거리 보정`(패턴)으로 잡는다 |
| 두 배우 마크가 서로 안 맞는 것 같음 | 맞출 필요가 없다 | 두 임팩트는 **정의상 같은 시각(t=0)**이다. 각자 자기 모션에만 맞춘다 |

## 참고 — 구현 중 발견해 고친 것

**`MeshSliceBaker`의 원래 버그 2개** (이번 전환과 무관하게 존재했으나 적 사망 절단에서 바로 터질 자리였다)

1. **"실제로 갈렸는가" 판정** — 삼각형 개수로 재고 있었다. 평면에 딱 얹힌 면은 한쪽으로 배정되므로 스치기만 해도 양쪽에 삼각형이 생겨 오판 → 허공에 캡 생성. **평면 바깥에 지오메트리가 있는가**로 교체.
2. **부피 계산이 평행이동 불변이 아니었다** — 발산정리 합은 닫힌 메쉬에서만 원점이 상쇄된다. 캡 없는 조각은 "원점→삼각형 뿔 부피"가 되어 원점에서 멀수록 부풀어, 두께 0인 조각이 퇴화 필터를 통과했다(실측 0.167). **자기 bounds 중심 기준**으로 교체.

1번이 2번을 가리고 있었다 — 캡이 앞뒤 두 겹으로 붙어 부피가 우연히 0으로 상쇄됐다. **적은 링 반경 밖(원점에서 멂)에 서므로 2번 오차가 정적 소품보다 훨씬 크다.**

**적 처치 시각 (`EnemyDirector`)** — 처치만 "임팩트 시각 = Deadline" 규율에서 빠져 있었다.
패턴 완료 이벤트는 마지막 노드를 **입력한 순간**에 뜨는데(Perfect면 Deadline보다 0.1초 이르다),
그때 바로 갈라뜨리고 있었다. **잘 칠수록 적이 칼보다 먼저 죽는** 상태였다.
성패 확정과 연출을 분리해 교체를 임팩트 시각에 예약하는 것으로 고쳤다.

**`SampleAnimation`이 배치를 덮어쓴다** — 클립을 샘플링하면 캐릭터가 **클립이 정한 자리로 옮겨진다.**
세워 둔 자리는 무시된다. 이걸 모르고 "배치 → 샘플링" 순서로 짜서 두 곳이 틀렸다:

- **짝 에디터** — 회전이 날아가 두 배우가 같은 방향을 봤다(적이 등을 돌림).
  루트 모션은 보여줘야 하므로 **중립에서 샘플링한 뒤 배치에 합성**하도록 고쳤다.
- **슬라이서 칼 평면 유도** — 플레이어가 옮겨진 자리에서 칼의 월드 위치를 읽어
  **엉뚱한 데를 자르는 평면**이 나왔다. 여기선 루트 모션이 필요 없으므로 **샘플링 후 배치를 복원**한다.

같은 원인, 다른 처방이다 — 루트 모션을 **보여줘야 하는 곳과 버려야 하는 곳**이 갈린다.
(`BakeMesh` 경로는 안전하다. 렌더러 로컬 공간으로 뜨고 bindpose는 world가 상쇄되어 배치와 무관하다.)

**정점 3배 폭증** — `AppendTriangle`이 삼각형마다 정점을 새로 만들어 결과 정점 수가 삼각형 수 × 3이었다.
정적 프롭에서는 무시할 만했지만 캐릭터 + `boneWeights`(32B/정점)에서는 메모리도, 매 프레임 스키닝 비용도 3배가 된다.
`ToMesh()`에 **속성 전체 일치 기준 용접**을 넣었다. 정적 경로도 같이 이득을 본다.
