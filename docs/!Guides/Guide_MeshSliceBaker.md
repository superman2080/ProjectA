# Guide — Mesh Slice Baker (베이는 표적 굽기)

표적 오브젝트를 **미리 조각으로 잘라 구워두는** 에디터 툴 사용법. 런타임 메쉬 절단이 아니라, 굽어둔 조각 프리팹으로 교체하는 방식이다.

메뉴: **`Tools/Mesh Slice Baker`**

---

## 전체 흐름

```
원본 프리팹 지정 → 씬에서 획 긋기 → Preview로 확인 → Bake
                                                      │
                                                      ▼
                                    SliceSet 에셋 생성 (조각 Mesh + 조각 프리팹 포함)
                                                      │
                                                      ▼
                                    패턴 에셋의 sliceTargets에 드래그해서 배선
```

**중요 — Bake는 카탈로그에 자동 등록되지 않는다.** 구운 `SliceSet`을 실제로 쓰려면 `Pattern` 에셋의 `Slice Targets` 배열에 직접 넣어야 한다. 카탈로그를 두지 않기로 한 설계(패턴 → SliceSet 직접 참조)의 결과다.

---

## 1. 원본 준비

- 표적은 **MeshFilter + MeshRenderer**를 가진 프리팹이어야 한다.
- 메쉬의 **Read/Write Enabled**를 켜 둔다(임포트 설정). 꺼져 있으면 툴이 사유를 표시하고 굽기를 막는다.
- 스킨드 메쉬(캐릭터)는 지원하지 않는다.

## 2. 획 긋기

프리팹을 지정하면 **창 위쪽 프리뷰**에 모델이 나타난다. 씬에는 아무것도 만들어지지 않으므로 작업 중인 씬이 오염되지 않는다.

| 입력 | 동작 |
|---|---|
| **좌드래그** | 획 추가(절단 평면 1장 생성) |
| **우/중간 드래그** | 카메라 회전 |
| **휠** | 줌 |
| **Shift + 좌드래그** | 수평/수직/45° 스냅 |

1. 프리뷰에서 **좌드래그**하면 그 자리에 절단 평면이 생긴다.
2. **`Shift`**를 누르면 각도가 스냅된다 — 정확한 `┼`나 `X`를 만들 때 쓴다.
3. 여러 획을 그으면 교차한다. **가로 1획 + 세로 1획 = 4조각**, 3방향이면 8조각.
4. **우드래그로 카메라를 돌려** 다른 각도에서 그으면 임의 방향 평면을 만들 수 있다.

평면은 파란 사각형으로 겹쳐 표시되고, 획 목록에서 선택한 것은 노란색이 된다.

**획의 길이는 무시된다.** 짧게 그어도 메쉬 전체가 갈린다 — 획에서 쓰이는 정보는 **각도와 위치**뿐이고, 만들어지는 것은 무한 평면이다. 그래서 `T`자 같은 **부분 절단은 만들 수 없다**.

곡선이나 꺾인 획도 지원하지 않는다. 꺾인 모양이 필요하면 **직선 획 여러 개**로 표현한다.

### 프리셋에서 시작하기

`Shape` 드롭다운에서 `Horizontal`/`Vertical`/`Diagonal`/`Cross`/`Dice`를 고르면 해당 평면들이 획 목록에 채워진다. 거기서부터 손보면 된다. 프리셋을 수정하면 Shape가 자동으로 `Custom`으로 바뀐다(프리셋과 어긋난 채 `Cross`로 저장되는 혼동을 막기 위함).

**평면 장수는 Shape에 묶이지 않는다.** `Horizontal`을 고른 뒤 획을 더 그어도 되고, 3등분이 필요하면 획 2개를 그으면 된다.

### 획 다듬기

획 목록에서 각 획을 선택해 **법선/거리를 수치로 미세 조정**할 수 있다. 선택한 획은 씬에서 노란색으로 강조된다.

---

## 3. Preview로 확인

`Preview` 버튼은 에셋을 만들지 않고 결과만 보여준다.

**프리뷰가 실제 조각들로 바뀌고**, 좌하단 **분해 슬라이더**로 조각을 바깥으로 밀어 볼 수 있다. 의도한 대로 갈라졌는지 굽기 전에 눈으로 확인하는 용도다. 텍스트로는 이런 것들이 나온다.

- **조각 수** (퇴화 조각이 폐기됐으면 그 수도 함께)
- **머티리얼 슬롯 구성** — 캡이 들어갈 서브메쉬 인덱스와, 그 슬롯에 실제로 물릴 머티리얼 이름
- 조각별 **정점/삼각형 수, 캡 루프 수**

획을 추가하거나 수정하면 분해 프리뷰는 초기화된다 — 다시 `Preview`를 누르면 된다.

---

## 4. 단면 머티리얼

**비워도 된다 — 그게 정상 경로다.** 비우면 원본 머티리얼 `[0]`을 단면에도 그대로 쓴다. 표적 대부분이 단색/패턴 재질이라 겉면 재질로도 단면이 충분히 그럴듯하고, 단면 재질을 따로 만들지 않고 바로 구울 수 있다.

| 상황 | 동작 |
|---|---|
| 단면 머티리얼 지정 | 그것을 캡에 사용 |
| 비움 + 원본 머티리얼 1개 | 원본 `[0]`을 캡에 사용 (정보 로그) |
| 비움 + 원본 **멀티** 머티리얼 | 원본 `[0]`을 캡에 사용하되 **경고** — 몸통/테처럼 [0]이 단면에 안 맞을 수 있으니 확인하라는 뜻 |
| 원본 머티리얼이 비었거나 `[0]`이 null | **굽기 중단**(폴백 대상 없음) |

조각의 서브메쉬는 항상 **`원본 M개 + 캡 1개`**이고 머티리얼 배열도 `M+1`개다. 배열에 `null`이 들어가는 경로는 없다(마젠타 에러 셰이더 방지).

### Cap UV Scale

캡 UV는 절단 평면에 투영한 값이라 **오브젝트 크기에 따라 텍셀 밀도가 달라진다**. 원본 머티리얼을 단면에 그대로 쓰면 겉면과 단면의 밀도 차가 눈에 띌 수 있는데, 이때 `Cap UV Scale`(기본 1.0)로 맞춘다. 겉면 밀도에 자동으로 맞춰주는 기능은 없다.

---

## 5. Bake

`{출력 경로}/{세트 이름}/` 아래에 다음이 생긴다.

```
Piece_0.asset   … 조각 메쉬
Piece_0.prefab  … 조각 프리팹 (MeshFilter + MeshRenderer + SlicePiece)
Piece_1.asset
Piece_1.prefab
...
{세트이름}.asset … SliceSet
```

조각 프리팹에는 **콜라이더도 Rigidbody도 붙지 않는다.** 흩어짐은 물리가 아니라 트랜스폼 계산이다.

### 재굽기 (중요)

같은 이름으로 다시 구우면 에셋을 **제자리 수정**해 **GUID를 유지**한다. 카탈로그가 없어서 패턴 → SliceSet 직접 참조가 유일한 배선이므로, GUID가 바뀌면 **그 세트를 쓰던 모든 패턴의 배선이 끊긴다.**

기존 `SliceSet`이 있는 경로를 지정하면 툴이 **저장된 절단 평면을 로드**한다. 프리셋으로 되돌아가지 않으므로 손으로 맞춘 획이 그대로 재현된다.

획을 지워 조각 수가 줄면 남는 조각 에셋은 자동으로 정리된다.

---

## 6. 패턴에 배선

구운 `SliceSet`을 `Pattern` 에셋의 **`Slice Targets`** 배열에 넣는다.

| 필드 | 의미 |
|---|---|
| `Set` | 쓸 `SliceSet`. 비우면 그 표적은 무연출 |
| `Spawn Offset` | 임팩트 지점 기준 XY 배치. **칼 궤적 폭 안**에서 겹침을 피하는 용도로만 쓴다 |
| `Impact Offset` | 판정 종료 시각 대비 ±초. 표적 여러 개에 시간차를 줄 때 |

> **주의 — 표적은 패턴 템플릿에 묶인다.** 같은 템플릿을 쓰는 모든 자리에서 같은 표적이 나온다. 실측상 한 곡(102 엔트리)이 고유 템플릿 10개를 쓰고 최다 템플릿은 25회 반복되므로, **표적 연출의 다양성은 템플릿 수에 묶인다.** 곡별로 다르게 하려면 채보 데이터 모델 확장이 필요하다.

---

## 7. 씬 배선

`SliceTargetDirector`를 씬에 하나 두고 연결한다.

| 필드 | 설명 |
|---|---|
| `Handler` | `PatternHandler` |
| `Impact Anchor` | 칼이 지나가는 월드 지점. 표적은 여기로 다가와 갈라진다 |
| `Approach Duration` | 표적이 오는 데 쓰는 **희망** 시간(기본 1.5). 패턴이 짧으면 자동으로 잘린다 |
| `Approach Speed` | 접근 속도. **스폰 거리 = 속도 × 실제 접근시간** |
| `Scatter Speed/Jitter/Spin/Gravity` | 흩어짐. `Gravity` 0이면 직선, 아래로 주면 처지며 날아감 |
| `Debris Lifetime` / `Max Active Pieces` | 잔해 정리 |
| `Prewarm Sets` | 미리 채워둘 세트(선택). 비워도 동작한다 |

### 튜닝 순서

1. **`Approach Speed`를 최소 구간(≈1.14초) 기준으로 잡는다.** 스폰 거리가 `속도 × 실제 접근시간`이라, 1.5초 기준으로 맞추면 짧은 패턴(1노드)의 표적이 화면 안에서 튀어나온다. 최소 구간에서도 화면 밖에서 시작하도록 잡으면 긴 패턴은 자연히 더 멀리서 여유 있게 온다.
2. 임팩트 시각과 칼 궤적이 시각적으로 맞는지 확인.
3. `Scatter*`로 흩뿌림 감 조정.
4. `Debris Lifetime` / `Max Active Pieces`로 잔해 정리.

**표적 1개(`Spawn Offset = 0`)로 먼저 맞추고**, 다중 표적은 그 뒤에 폭을 조금씩 늘려가며 확인한다.

---

## 자주 걸리는 것

| 증상 | 원인 |
|---|---|
| 굽기 버튼이 비활성 | 창 하단 경고 확인 — 프리팹/세트 이름/Read-Write/평면 중 하나가 빠졌다 |
| 조각이 예상보다 많다 | 원본이 여러 덩어리이거나 절단으로 분리됐다. 연결 요소별로 나뉘므로 정상 |
| 조각이 예상보다 적다 | 퇴화 조각이 폐기됐다(획 2개가 거의 겹침). Preview의 폐기 수 확인 |
| 단면이 마젠타 | 이 툴로 구웠다면 발생하지 않는다. 조각 프리팹의 머티리얼을 수동으로 건드렸는지 확인 |
| 재굽기 후 패턴 배선이 풀림 | 세트 이름/경로를 바꿔서 새 에셋이 만들어진 경우. 같은 이름·경로로 구워야 GUID가 유지된다 |
