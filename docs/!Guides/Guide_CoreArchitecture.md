# Guide_CoreArchitecture — 판정 · 클립 정렬 · 이벤트

이 게임의 코어를 이루는 세 축을 코드 기준으로 정리한 문서다. 새로 합류했거나 오랜만에 돌아온 사람이
`PatternHandler` · `ClipAlignment` · 이벤트 배선을 한 번에 훑기 위한 것이다.

세 축은 한 줄로 이어진다:

```
판정이 Deadline을 만든다 → 클립 정렬이 그 Deadline에 임팩트를 맞춘다 → 이벤트가 그 사실을 모두에게 알린다
```

---

## 1. 판정 시스템

소유자는 `PatternHandler` 하나다. 판정에 관해 다른 클래스는 전부 구독자다.

### 1-1. 상태를 두 곳으로 나눈다

| 타입 | 성질 | 드는 것 |
|---|---|---|
| `Pattern` (ScriptableObject) | 모양 원본, 진행 상태 없음 | 노드 인덱스 나열, 클립 슬롯 |
| `ActivePattern` (일반 C# 클래스) | 재생 중인 패턴 하나의 런타임 상태 | `CurrentPosition`, `AllCorrect`, 입력 시각, `Deadline` |

분리한 이유: 같은 템플릿을 쓰는 두 패턴이 동시에 살아 있을 수 있다. 에셋에 진행 상태를 두면 서로를 덮어쓴다.

### 1-2. 큐는 여럿, 판정 대상은 하나

`activePatterns` 리스트에 여러 패턴이 동시에 산다. 노출 리드타임(0.5초)이 엔트리 간 입력 간격(최소 0.4초)보다
길어 노드 스폰이 겹치기 때문이다. 반면 **입력 시각은 겹치지 않으므로** `JudgeTarget`은 언제나 리스트 선두 하나다.
선두가 완료/만료되면 같은 프레임에 다음이 승계된다.

### 1-3. 시각의 기준점

- `StartTime` = 큐 투입 시각으로 **고정**. 노드별 입력 시각이 이 값 기준 상대시간이라, 승계 때 다시 잡으면 타이밍이 통째로 밀린다.
- `Deadline` = 마지막 노드 시각 + `goodWindow`. **판정 종료점이자 절단·사망 클립·카메라·히트스톱의 공통 임팩트 앵커**다.

### 1-4. 판정 함수

```csharp
private JudgementResult Judge(float delta)
{
    if (delta <= perfectWindow) return JudgementResult.Perfect;
    if (delta <= goodWindow)    return JudgementResult.Good;
    return JudgementResult.Miss;
}
```

`delta = |Time.time - target.ExpectedTime|` — 절댓값이라 이르든 늦든 대칭이다.
윈도우 두 값은 **씬별 직렬화 필드**다. 전투 씬 0.05 / 0.10, 튜토리얼 씬 0.10 / 0.25.
난이도 손잡이가 코드가 아니라 씬에 있다.

### 1-5. 입력 하나가 지나가는 경로 (`AddPattern`)

- **오답 인덱스** — `AllCorrect`만 끄고 Miss 색을 칠한 뒤 즉시 반환. 진행하지 않으므로 패턴이 정체한다.
  첫 오답에서만 `OnJudgeTargetFirstMiss`가 난다.
- **정답 인덱스** — `Judge(delta)`로 결과를 내고, **Miss여도 `Advance()`로 진행**한다.
  정답 노드 위의 타이밍 Miss는 통과시킨다는 뜻이다.

마지막 노드가 판정되면 그 자리에서 `CompletePattern`이 돌아 다음 패턴이 즉시 승계된다.

### 1-6. 놓친 노트는 이벤트로 오지 않는다

`OnJudged`는 친 노트에서만 난다. 오답은 조기 반환이고 무입력은 아예 판정되지 않는다.
그래서 채점은 **패턴이 끝날 때의 뺄셈**이다: `전체 노드 수 − 그 패턴에서 난 OnJudged 수`.

`ExpireOverduePatterns`가 매 프레임 회수를 맡는다. 회수 시각을 넘겼는데 완료되지 않았으면
`MarkIncorrect`를 걸고 완료 처리한다.

### 1-7. 비대칭 하나가 조작감이 된다

중간 노드는 아무리 늦어도 회수 전이면 입력이 먹고 진행된다. **마지막 노드만 허용치가 `goodWindow` 그 자체**다.
그 뒤엔 패턴이 이미 회수돼 색도 소리도 없이 삼켜진다.

`judgeGraceDuration`이 그 창만 넓힌다(`ExpiryTimeOf`). **`Deadline`은 안 민다** — 임팩트 앵커이기 때문.
판정 결과도 안 바꾼다(늦으면 여전히 Miss). 뒤에 대기 패턴이 있거나 연타면 유예가 사라진다.
곡 재생 중에는 대기 패턴이 거의 항상 있어 사실상 튜토리얼 전용 손잡이다.

### 1-8. 입력 계층의 가드 셋

| 가드 | 하는 일 | 예외 |
|---|---|---|
| `connectedIndices` | 같은 Point는 패턴당 한 번 | 지금 기다리는 노드는 제외 |
| `IsWithinHandover` | 승계 후 0.08초 입력 차단 | 연타 제외 |
| `GetPassThroughIndex` | 직선이 지나는 중간 노드 자동 입력 | `a == b`면 −1 |

- **중복 가드에서 현재 대기 노드를 빼는 이유**: `connectedIndices`에는 오답도 쌓인다. 예외가 없으면
  뒤에 나올 노드를 순서 전에 한 번 스친 순간 그 노드가 그 패턴에서 영영 막힌다.
- **승계 무시 구간**: 완료와 승계가 같은 프레임이라 마지막 타의 여운(더블탭·키 채터링)이 다음 패턴 첫 노드로
  새어 큰 음수 delta로 Miss를 먹였다. 엔트리 최소 간격이 0.4초라 정상 입력은 안 걸린다.
- **`a == b` 반환**: 중점 식이 그 경우 자기를 돌려주는데 `ForceDown`이 `OnPointPressed`를 다시 부른다(무한 재귀).

### 1-9. 연타는 같은 파이프라인의 다른 물음

`Pattern.isMash`면 `AddPattern`이 `HandleMashHit`으로 빠진다. 아무 인덱스나 유효타이고 타이밍을 안 본다
(창 안의 모든 타격이 Perfect). `IsComplete`의 뜻도 갈린다 — 노드를 다 소비했는가가 아니라 **목표 타수를 채웠는가**.

핵심 규칙 둘:

- **타수를 채워도 완료하지 않는다.** 완료는 회수 루틴이 `Deadline`에 한 번만 한다.
  그 자리에서 완료하면 다음 패턴이 같은 프레임에 승계돼 초과 타격이 그 패턴의 입력으로 샌다.
- **입력 마감은 `Deadline`보다 마무리 일격의 와인드업만큼 이르다**(`MashInputDeadline`).
  마감을 아는 곳이 하나여야 입력 가드와 링 수축 시간이 같은 값을 본다.

### 1-10. 디버그 입력이 판정을 우회하지 않는다

에디터 전용 강제 입력은 `debugForcedResult`를 세우고 `ForceDown`을 부른다.
분기는 `debugForcedResult ?? Judge(delta)` 한 줄뿐이라 나머지 경로가 전부 실제와 같다.

## 2. 클립 정렬 시스템

계산은 `Pattern/Core`의 `ClipAlignment` · `ClipSequence` 두 순수 클래스가 하고,
배우 둘(`CharacterActionPlayer` · `EnemyView`)이 그것을 각자 쓴다. asmdef가 분리돼 있어 유닛테스트가 붙는다.

### 2-1. 앵커는 시각 하나

```
impactAlignTime = Deadline + Pattern.ImpactOffset
```

이 식은 `PatternInfoExtensions`에 **한 번만** 적혀 있고 세 페이로드가 확장 메서드로 공유한다.
이 한 순간에 다섯이 동시에 맞춰지기 때문이다 — 플레이어 칼, 적 칼, 시체 절단, 투사체 도착, 카메라 큐.
식이 복제되면 하나만 어긋나는데 화면에서는 "칼은 지나갔는데 뒤늦게 갈라진다"로만 보인다.

### 2-2. 맞추는 것은 임팩트 프레임이지 시작도 끝도 아니다

플레이어 공격 클립과 적 클립은 길이도, 저작 배속도, 압축을 유발하는 제약도 다르다
(플레이어는 다음 패턴까지의 여유, 적은 처치 확정~임팩트 간격). **배속이 같아질 이유가 없다.**

그래서 시작이나 끝을 맞추는 정렬은 원리적으로 성립하지 않는다 — 시작을 맞춰도 배속이 다르면 임팩트가 어긋난다.
각 배우는 같은 절대 시각에 자기 임팩트 프레임이 오도록 **자기 시작 시점과 자기 배속을 역산**한다.
그래서 두 메서드가 전부 `impactAlignTime`을 받는다.

### 2-3. `ClipAlignment`의 필드와 역산

| 필드 | 뜻 |
|---|---|
| `clip` | 비면 무연출 |
| `startOffset` | 트림 시작(선딜 제거) |
| `duration` | 트림 길이, 0이면 클립 끝까지 |
| `impactTime` | 칼날이 지나가는 **클립 절대 초** |
| `speed` | 저작 배속(하한으로 쓰인다) |
| `extraImpactTimes` | 마지막 베기 이전의 칼질들(다중 히트스톱 전용) |

파생값 하나가 전부를 움직인다:

```
ResolvedImpactSpan = impactTime − startOffset      // 트림 시작 → 임팩트
```

미오서링(0 이하)이거나 트림 범위 밖이면 **트림 끝으로 폴백**한다. 값이 없는 데이터도 그대로 돈다.

```
ResolveScheduleStart(align, earliest) = max(align − ResolvedImpactSpan / Speed, earliest)
ResolvePlaySpeed(now, align, max)     = clamp(ResolvedImpactSpan / (align − now), Speed, max)
```

`earliest`는 첫 노드 시각이다. 노드가 나오기 전에 휘두를 수는 없다.

### 2-4. 배속이 클립 전체에 걸린다는 함정

`ResolvePlaySpeed`는 임팩트 **이전** 구간만 보고 배속을 정하는데 Animator의 Speed Multiplier는
클립 전체에 걸린다. 그래서 **`ImpactTime`을 뒤에 찍을수록 마무리 동작까지 빨라진다.**

적 사망 클립에서 직접적이다. 재생 시작이 처치 확정 순간이고 임팩트까지 남는 실시간이
`goodWindow` + 보정뿐이라, **사망 클립의 임팩트는 트림 시작 근처에 찍어야 한다.**
뒤에 찍으면 정렬이 깨지기 전에 쓰러지는 속도부터 빨라진다.

### 2-5. 클립 여러 개를 잇는 경우 (`ClipSequence`)

`Pattern.playerLeadInClips`가 활성 슬롯 **앞에** 붙는다. 슬롯을 리스트로 갈아엎지 않은 이유는
**마지막 클립이 곧 정렬 앵커**여서다 — 앵커를 제자리에 두면 기존 템플릿의 마이그레이션이 0이고
칼 평면 유도·이펙트 프리뷰가 한 줄도 안 바뀐다.

단위가 **'저작 초'**로 통일된다. 원소마다 저작 배속이 달라 클립 초를 그냥 더하면 의미가 없다.

```
AuthoredSpan = Σ(리드인 트림 / 저작배속) + (마지막 임팩트스팬 / 저작배속)
ratio        = max(AuthoredSpan / available, 1)
원소 i의 애니메이터 배속 = speed_i × ratio
```

비율 하나가 시퀀스 전체에 걸린다. 창이 모자라면 원소를 자르는 게 아니라 **전부 같은 비율로 빨라진다.**
실시간 합이 정확히 창과 같아져 마지막 임팩트가 제시각에 도착한다.

리드인이 비면 `AuthoredSpan`이 `ResolvedImpactSpan / Speed`와 **대수적으로 동일**하다.
이 항등식이 회귀 없음의 보장 전부다.

배속 상한이 원소 수로 갈린다 — 1개면 `maxAttackSpeed` 유지, 2개 이상이면 상한을 안 건다
("전부 재생된다"가 요구라 상한과 양립하지 않는다). 넘으면 경고를 찍는다.

### 2-6. 재생 헤드가 저작 초로 일원화돼 있다

```
headAuthored += elapsed * playSpeed / playingBaseSpeed;
DuelCurveTime = HeadAuthoredNow() − impactAuthored;
```

월드 시각(`Time.time − impactTime`)을 쓰면 안 되는 이유 셋:

1. 히트스톱은 배속을 0으로 만들 뿐 `Time.time`은 계속 흐른다 → 캐릭터는 얼었는데 몸만 미끄러진다.
2. 배속 압축이 걸리면 칼 리치와 간격의 대응이 깨진다.
3. 정지 예산은 재생을 미리 앞당긴다.

재생 헤드에서 파생하면 셋 다 공짜로 성립한다.

단위가 둘인 것은 소비자가 둘이라서다 — 추가 히트스톱 마크는 **그 원소의 클립 초**로 저작되고,
거리 커브와 임팩트 판정은 **시퀀스 전체의 저작 초**를 본다. 배속이 바뀌는 모든 지점이
`CommitHeadProgress`를 불러 두 시계를 함께 민다.

### 2-7. 정지가 정렬을 안 깨는 방법 둘

한 클립 안에서 여러 번 베면 칼질마다 멈춘다. 정지 N회 × 정지 길이만큼 클립이 안 흐르는데
마지막 베기는 여전히 제시각에 도착해야 한다.

- **예산**(주 경로) — 재생을 그 총량만큼 일찍 시작한다. 배속을 안 건드려 모션이 안 뭉개진다.
- **따라잡기**(보정) — 정지를 풀 때마다 `남은 임팩트 스팬 ÷ 남은 실시간`으로 **시퀀스 비율**을 다시 잡는다.
  원소의 배속이 아니라 비율을 고치는 이유는 남은 스팬이 원소 경계를 넘을 수 있어서다.

정지 길이는 `HitStopDirector`에서 당겨 온다. 히트스톱이 꺼져 있으면 0을 돌려주므로
예산과 실제 정지가 자동으로 일치한다.

`IsBeforeImpact()`가 두 경로를 가른다. **임팩트를 지난 뒤에만 복귀 스케줄을 민다.**
아직 전이면 미는 순간 마지막 베기가 절단보다 늦어진다.

### 2-8. 슬롯과 폴백 방향

`Pattern`이 드는 `ClipAlignment` 슬롯 일곱: 플레이어 공격/패링, 적 공격/견제/피격/패링/사망.
전부 같은 규칙으로 정렬되지만 **폴백 방향이 둘로 갈린다**.

- **견제** — 닿지 않는 동작이라 임팩트를 안 찍는다. 트림 끝이 임팩트가 되어 **클립 끝이 임팩트 시각에 붙는다**.
- **리액션** — 맞는 순간이 곧 시작이라 미지정이면 **임팩트에 시작**한다.
  기본 폴백을 그대로 쓰면 맞기도 전에 다 젖혀져 있다.

저작은 `Tools/Animation Clip Trimmer`(Start / Impact / End).

## 3. 이벤트 아키텍처

규칙은 하나다: **`PatternHandler`는 판정만 하고 아무것도 구독하지 않는다.**
연출과 채점은 전부 그 이벤트를 구독하는 순수 소비자다. 그래서 카메라·히트스톱·점수·실루엣을 붙이면서
판정 코드를 한 줄도 고치지 않았다.

### 3-1. 허브와 소비자

| 이벤트 | 발행 순간 | 주요 구독자 |
|---|---|---|
| `OnPatternQueued` | 큐 투입 | 표적, 적, 월드 이펙트 |
| `OnJudgeTargetBegan` | 선두 승계 | 캐릭터 액션, 카메라, 튜토리얼 |
| `OnJudged` | 노트 판정 | 점수 |
| `OnJudgeTargetFirstMiss` | 첫 실패 | 캐릭터 액션, 적 |
| `OnFocusRingResolved` | 링 판정 | 이펙트, 효과음 |
| `OnPatternComplete` | 완료/만료 | 카메라, 히트스톱, 점수, 이펙트, 실루엣, 적 |
| `OnMashHit` | 연타 타격 | 캐릭터·히트스톱·게이지·적·이펙트 |
| `OnAllPatternsCleared` | 곡 중단 | 잔존물 회수 |

구독은 전부 단방향이다. 소비자가 허브를 다시 부르는 경로가 없다.

### 3-2. 시각이 다른 이벤트가 셋으로 갈린다

한 패턴의 생애에서 서로 다른 세 순간이 각각 이벤트를 갖는다.

1. **큐 투입** — 판정 대상이 되기 훨씬 전. 등장에 시간이 걸리는 연출(날아오는 표적)이 쓴다.
2. **선두 승계** — 입력을 받기 시작하는 순간. 공격 클립 예약이 여기서 선다.
3. **완료** — 마지막 노드가 판정된 순간. 성패가 확정된다.

이 분화가 규칙을 낳는다: **큐 시점에 이 패턴의 적을 정하면 안 된다.**
다음 패턴의 상대는 지금 패턴의 성패가 정하는데 그 답이 아직 없다. 리드타임 0.5 > 간격 0.4라
다음 패턴이 먼저 큐에 오르므로, 큐에서 상대를 잡으면 **한 명씩 밀린 상대**가 잡힌다.
그래서 `EnemyDirector`는 큐에서 예약만 만들고 배정은 선행 예약이 확정되는 순간에 한다.

### 3-3. 완료와 임팩트가 다른 시각이다

완료 = 마지막 노드 입력. 칼이 닿는 것은 거기서 `goodWindow`만큼 뒤다.
그래서 타격 연출은 완료 이벤트를 받은 자리에서 바로 쏘지 않고 **예약**한다:

```
예약 시각 = info.ImpactTime() = Deadline + ImpactOffset
```

카메라 쉐이크·히트스톱·임팩트 효과음·실루엣이 전부 이 식으로 예약한다.

**예약이 최대 하나면 되는 근거**: 패턴 완료가 순차적이고 다음 완료가 최소 0.4초 뒤라 리스트가 필요 없다.
이 근거가 깨지는 곳이 둘 — 다중 히트스톱(한 패턴이 정지를 여러 개 낸다)과 월드 이펙트 큐
(패턴 시작까지 앞당겨져 앞 패턴의 임팩트 큐와 겹친다). 둘 다 리스트를 쓴다.

### 3-4. 페이로드는 불변 구조체

`PatternCompletionInfo` · `JudgeTargetInfo` · `PatternQueuedInfo` · `MashHitInfo`.
인자를 나열하지 않고 구조체 하나를 넘긴다 — 필드가 늘어도 기존 구독자 시그니처가 안 깨진다.

셋이 **같은 것을 같은 이름으로** 부른다(`Template` · `Deadline`). 그래서 확장 메서드 하나가 셋을 다 받는다.

`MashHitInfo`가 `Template`을 싣고 다니는 이유: 안 실으면 적·이펙트가 "지금 판정 대상"을 큐에서 다시
유도하게 되고, 그게 바로 상대 배정을 어긋나게 했던 부류다.

### 3-5. 이름이 뜻을 정확히 말해야 한다

- **`OnFocusRingMissedArrival`을 채점에 쓰면 안 된다.** 이름은 "놓쳤다"지만 아니다 —
  수축 완료는 `ExpectedTime` 정각에 발행되는데 판정 창은 거기서 `goodWindow`만큼 더 열려 있다.
  **늦은 쪽 Perfect/Good이 전부 이 이벤트를 먼저 발행**하므로, 이걸로 콤보를 끊으면 정확히 친 노트의
  절반이 콤보를 끊는다.
- **`OnJudgeTargetFirstMiss`도 채점에 안 쓴다.** 쓰면 패턴이 정체하는 동안 콤보가 두 번 끊긴 것으로 읽힌다.
- **놓친 노트는 이벤트로 오지 않는다.** 채점은 완료 시점의 뺄셈이다(§1-6).

### 3-6. 이벤트가 '확정'과 '사건'으로 갈린다

`EnemyDirector`의 둘이 대표적이다.

| 이벤트 | 시각 | 화면 |
|---|---|---|
| `OnEnemyKilled` | 처치 **확정** | 아직 아무 일도 없다 |
| `OnEnemyBurst` | **절단** = 임팩트 | 사건이 일어난다 |

카메라 쉐이크는 후자를 듣는다. 확정에 걸면 칼이 닿기도 전에 화면이 흔들린다.

같은 분화가 `CharacterActionPlayer.OnPlayerHit`에도 있다 — 첫 미스 순간이 아니라 **적 칼이 실제로 닿는 시각**에
난다. 그래서 목숨 감소와 피격 카메라 큐가 그 이벤트 하나에 매달려 있고,
"적 공격을 못 막았을 때만 깎인다"는 규칙이 코드 분기 없이 **발행 조건으로** 표현된다.

### 3-7. 층이 서로를 안 만진다

`HitStopDirector`는 카메라를 안 만지고 `CameraDirector`는 애니메이터를 안 만진다.
히트스톱이 카메라를 얼려야 할 때도 **창을 알려 줄 뿐**이고 Cinemachine 호출은 전부 카메라 쪽에 남는다.
파티클도 마찬가지다.

효과음도 층이 든다. `SoundManager`는 게임플레이를 모르고 트리거 요청만 받는다.

### 3-8. 카탈로그가 코드 수정을 없앤다

연출 추가 = 카탈로그 한 줄. `EffectCatalog`(트리거 → 프리팹) · `CameraCueCatalog`(트리거 → 쉐이크 설정).
프리팹이 비면 무연출이다.

**키를 코드가 정하는 한계도 같이 온다** — 패턴마다 다른 임팩트음이 필요한데 트리거 enum은 패턴 수만큼 못 늘린다.
그래서 패턴별 소리는 이펙트 큐가 데이터로 든다. 큐에 얹으면 시각·조건·개수·툴 타임라인이 전부 따라온다.

### 3-9. 구독 해제가 곧 복구 경로다

배선이 비면 조용히 비활성되는 것이 공통 규율이다. 그런데 **상태를 남기는 소비자는 해제 경로를 빠짐없이 갖춰야 한다.**

- 카메라는 잠금 도중 꺼지면 **영구히 굳는다**.
- 실루엣은 시간 배율 복구 경로가 셋이다 — 노출 종료 · 곡 중단 · `OnDisable`.
- 콤보 포스트FX는 `OnDisable`에서 가중치를 0으로 안 되돌리면 **화면이 붉게 굳는다**.

`OnAllPatternsCleared`가 그 중간 경로다 — 곡이 중단됐을 때 외부 연출이 잔존물을 회수한다.
